## Question

基于火山引擎官网和官方文档，确认 DataLeap 中“逻辑表”的正式定义、来源与所在模块；按页面入口、前置条件、创建或注册步骤、创建表单字段、权限／上线关系、管理操作与 API 等下游使用还原全过程，并盘点数据资产列表与详情页展示的逻辑表信息和字段。保留官网原词、直接 URL、访问日期与页面／官方截图证据；优先复用但必须重新核验仓库内既有 DataLeap 一手资料，区分正文事实、截图观察和无法证实项。研究结果写入 `docs/research/sources/volcengine-dataleap-logical-table.md`。

## Answer

已完成：[火山引擎 DataLeap：逻辑表创建、管理、使用与资产页信息](../../../docs/research/sources/volcengine-dataleap-logical-table.md)。

精炼结论：DataLeap 数据服务的逻辑表是物理表的虚拟映射，标准流程为数据源 → 注册物理表 → 极简批量／标准单表／物理表同名方式创建逻辑表 → 项目授权或逻辑表集市申请 → API 使用。创建表单覆盖来源类型与物理表、字段中文名／描述／安全等级、查询约束、默认授权项目、目录、逻辑表名、L1-L4 安全等级、描述及下游 API 发布审核／通知。创建后可编辑字段与映射、切换物理表、授权／回收、预览探查、版本回退、标签、负责人、移动、主备与删除；有关联 API 时不能删除。逻辑表本身未见独立发布状态，保存即完成创建；“上线”只出现在备份物理表切流，下游审批发生在 API 发布。

资产侧应区分两处：可验证的逻辑表资产页是 `数据服务 > 数据集市 > 逻辑表集市`，其列表官方截图可见数据源类型、逻辑表名、负责人、最近更新时间、所属项目，详情展示基础信息、字段、预览探查、授权和变更记录；通用 `数据地图 > 数据检索` 当前官方类型清单未列 OneService 逻辑表，不能声称二者已经打通。报告保留官网原词、直接 URL、访问日期、页面更新时间与官方原图，并把截图字段单列为“页面观察”。
