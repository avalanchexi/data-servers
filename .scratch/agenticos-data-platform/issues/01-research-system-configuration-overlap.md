# 调研数据服务域设置与 AgenticOS 系统配置重叠

Type: research
Status: resolved
Claimed by: background research agent
Parent: ../map.md
Blocked by: none

## Question

基于数据服务原型与既有决策、AgenticOS 前端源码、最新 Playwright 系统管理采集，逐项比较数据服务域设置与 AgenticOS 系统配置及相关公共管理模块：哪些只是界面或名称相似，哪些实际维护同一业务对象、策略或事实源？

输出必须覆盖配置对象、字段或策略、作用范围、管理角色、事实源、运行执行方、审计方式、重叠等级和建议归属，并特别检查集市产品类型、认证与密钥策略、类型专属限制、环境与应用配置、字典、权限、安全策略和网关相关配置。

## Answer

已完成[数据服务域设置与 AgenticOS 系统配置重叠分析](../../../docs/research/agenticos-data-service-settings-overlap.md)。

核心结论：

1. 当前没有证据证明存在两套已运行的配置事实源：数据服务设置仍是刷新即丢失、不下发执行器的离线原型；AgenticOS 系统配置、应用配置、字典、权限、安全和审计才有当前生产读取证据。
2. 集市产品类型与系统字典、数据服务逻辑环境与当前 `config.yaml`“环境配置”、数据应用与 AgenticOS“应用配置”均只是名称或界面相似，业务对象不同，不应合并事实源。
3. 认证与密钥策略、类型专属限制属于跨层交集：数据服务维护数据应用级默认值、授权额度和绑定，AgenticOS 维护平台安全底线、秘密材料与运行时硬上限，网关和各类运行时接收执行投影。
4. 最需要消除的职责冲突是授权主体：现有资产中心源码用“角色 + 资产 ACL”表达数据服务授权，而目标数据服务以数据应用作为外部运行授权主体。前者只能约束平台内人员或提供资产安全边界，不能替代后者。
5. 系统审计应作为公共审计事实源，数据服务和资产安全只提供领域投影；当前多个审计 API 的物理存储关系仍需后端核实。
6. 当前未发现厂商中立的网关路由、发布、漂移和回滚事实源。物理网关实例、适配器和秘密引用应归 AgenticOS 公共底座，数据服务拥有本域期望配置和发布意图。
