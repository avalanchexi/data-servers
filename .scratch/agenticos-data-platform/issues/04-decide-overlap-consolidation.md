# 确定重叠功能的单一归属与收敛策略

Type: grilling
Status: resolved
Claimed by: Codex
Parent: ../map.md
Blocked by: 01, 02

## Question

基于系统配置重叠和运行监控重叠的事实矩阵，逐项决定哪些能力由 AgenticOS 公共底座统一拥有、哪些由数据服务域独立拥有、哪些只在数据服务中提供只读投影或场景入口，以及原型中的重复页面应保留、合并、改为引用还是弃用。

运行监控方向已经确定为不合并；本票仍需决定两个模块如何共享指标标识、异常关联、审计上下文与下钻入口。跨域及底层配置原则上由 AgenticOS 公共底座统一管理和建设，具体重叠项待系统配置调研后逐项裁决。

## Answer

已完成单一归属与收敛决策。总体采用“公共底座拥有跨域事实与执行设施，产品域拥有领域意图和场景视图；共享控制与审计框架，不合并领域对象”的原则。

| 重叠能力 | 单一事实／控制归属 | 另一侧的保留方式 | 原型处置 |
| --- | --- | --- | --- |
| 人员、组织、角色、菜单和平台功能权限 | AgenticOS 权限管理 | 数据服务按登录主体消费判定结果 | 删除数据服务中的重复编辑页，只保留无权限提示或只读引用 |
| 开发者资产发现、字段／行范围及分类分级约束 | 资产中心数据安全／数据治理 | 数据服务在开发和审批中展示申请入口及生效结果 | 保留场景入口，不复制资产 ACL 或规则维护页 |
| 数据应用及平台服务身份的运行授权 | 数据服务域拥有服务授权业务事实，统一工作流拥有审批过程 | 公共授权框架提供申请、生效、撤销、策略判定和审计机制 | 保留“应用与授权”，不以平台角色或资产权限替代运行授权 |
| 公共审计 | AgenticOS 公共审计事件为唯一不可变事实源 | 数据服务按领域对象、授权和调用链提供投影 | 两个查询入口均保留；数据服务页改为公共审计的领域读模型 |
| 租户、环境、网关实例、适配器、连接、密钥引用和基础设施状态 | AgenticOS 系统管理 | 数据服务只引用环境、网关绑定和连接状态 | 数据服务设置中的重复编辑器删除或改为只读链接 |
| 能力注册、类型、版本、准入及可授权状态 | AgenticOS 能力中心 | 数据服务开发与数据应用固定引用已批准版本 | 保留业务选择器，删除第二套能力注册页 |
| 集市产品类型展示、域内认证规则和类型专属限制 | 数据服务域设置；不得突破数据安全公共底线 | 公共底座与网关消费运行投影 | 数据服务设置保留三个目录项，不承载系统或基础设施配置 |
| 数据服务路由意图、策略绑定、配置发布、漂移、紧急停流和服务健康 | 数据服务运行管理 | 公共网关底座拥有适配执行和实际状态 | 数据服务保留完整控制页；系统管理只维护实例和适配器 |
| 系统组件与数据服务监控 | AgenticOS 系统监控拥有调度、日志、缓存、存储和公共组件诊断；数据服务运行管理拥有服务／应用健康及领域处置 | 共享原始遥测、事件、审计、稳定 ID 和时间上下文并双向下钻 | 两个入口均保留，不复制写操作或破坏性动作 |
| 请求认证与调用授权 | 数据服务域与统一工作流拥有业务授权事实；统一网关负责请求时认证、路由级允许／拒绝、入口配额；数据安全域与数据引擎负责最终数据权限 | 网关只执行授权运行投影并产生公共审计事件 | 不新增“网关业务审批”或“网关数据权限”页面 |

能力与消费关系采用两段审批、两类投影：

1. API、Agent、MCP、模型、数据流及托管 Worker 等在线能力完成开发或注册并通过上线审批后，形成网关运行投影；Skill 文件和 Worker 模板等离线包只注册、签名和分发。
2. 数据应用或平台服务身份申请固定能力版本，并在环境、数据和操作范围内获得审批后，才把调用授权策略下发网关。能力上线不自动授予任何消费主体调用资格。

数据应用继续作为外部消费场景的逻辑治理与装配边界，不要求成为固定网络跳点；平台托管时可以承载消费逻辑，外部运行时只形成身份和治理映射。AgenticOS 内部 Agent 或业务应用使用对应数据应用身份，公共底座后台任务使用组件独立的平台服务身份；两者均显式授权并完整审计，不设置 AgenticOS 整体超级身份或内部免鉴权旁路。

两个监控入口的操作边界最终确定为：AgenticOS 系统监控可以执行公共组件诊断以及调度、日志、缓存和存储等平台运维动作，但不能编辑数据服务路由、授权或配置发布；数据服务运行管理可以执行策略绑定、配置发布、紧急停流和领域异常处置，但不能清理公共日志、缓存或操作底层调度器。系统内组件合法调用网关能力属于受管消费流程，不由任何监控页面权限自动取得。
