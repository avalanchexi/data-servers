# 判断 AgenticOS 作为数据中台基座的采用边界

Type: grilling
Status: resolved
Claimed by: Codex
Parent: ../map.md
Blocked by: 03, 04

## Question

基于架构能力矩阵与重叠功能收敛决策，判断 AgenticOS 能否直接、经补强后或不适合作为数据中台基座；确定数据中台四个产品域与 AgenticOS 公共底座的目标边界、必须先补齐的阻断能力、可后续演进的能力，以及进入总体设计、ADR 和实施规格所需的证据门槛。

## Answer

AgenticOS 采用“有条件采用”，可以作为当前数据中台应用层目标原型的公共底座，但不能依据现有前端与系统页面直接宣称已经具备生产级数据中台架构。

### 目标原型边界

```text
AgenticOS 产品壳层
  ├─ 数据中台应用层
  │    数据资产｜数据工程｜数据治理｜数据服务
  └─ AgenticOS 公共底座
       身份权限｜系统配置｜工作流｜统一网关｜能力治理｜系统监控｜公共审计

底层采集、存储、计算、调度和网关执行设施
  只在应用层对象和状态中被引用，不展开集群管理控制台
```

数据资产、数据工程、数据治理和数据服务通过逻辑上的数据平台控制面保持对象归属、版本、授权意图和生命周期一致；这一边界不要求首期拆为四套微服务，也不在当前原型中设计后端或部署拓扑。现有数据服务原型保持当前详细程度，其他三个产品域采用“平台骨架＋关键链路”，只展开足以说明应用层边界的导航、核心对象、列表／详情、关键表单、主要状态和跨域入口。

### 原型必须表达的内容

- 数据资产：目录、资产详情、血缘、开发者数据权限入口；
- 数据工程：数据源、任务开发、发布、调度实例、失败重跑和业务 SLA 入口；
- 数据治理：标准、质量、分类分级、数据权限、安全策略和问题处置入口；
- 数据服务：沿用现有服务开发、服务集市、数据应用、应用与授权、审批、运行管理和设置深度；
- 公共底座：复用 AgenticOS 现有页面和交互语言，通过引用与下钻体现，不在数据中台重复建设；
- 两条关键关系链在交互层能够走通：数据生产治理链，以及 ADS 资产到受管调用主体、网关调用和公共审计的数据服务消费治理链。原型只模拟关键状态，不实现真实执行。

### 明确排除的范围

当前不设计集群部署、弹性伸缩、集群版本／节点／标签、Spark／Flink／Hive／YARN 等引擎配置、基础设施作业、节点级精细监控、原始日志检索、集群安全、资源租户和备份恢复。图中这类“集群管理”属于架构层或运维层，不属于数据中台应用层原型。

同名能力不得误删：数据工程任务实例、失败重跑和业务 SLA，数据治理的数据安全与权限，数据服务配置发布、服务运监、异常和调用审计，以及 AgenticOS 系统监控的引用与下钻均继续保留。它们回答应用层对象是否正常，不负责底层集群如何部署和运行。

### 证据与后续门槛

`frontend/agenticos-asset-center-frontend/agenticos-asset-center-frontend/` 按当前项目的资产中心前端工程使用，是页面行为与 API 客户端契约的一手源码；其工程副本不含后端和完整应用入口的事实，只限制后端结论，不降低其前端证据等级。Playwright 采集用于证明当前部署系统的壳层、系统管理页面和只读运行事实，`prototypes/` 用于表达目标交互。三者已经足以支持本轮目标原型，但不足以证明后端实现或生产可用性。

当前阶段不补充后端源码、数据库模型、部署拓扑、性能容量或容灾证据，不创建详细 ADR、实施规格、迁移计划或生产验收方案；继续维护单一 `CONTEXT.md`。应用层原型验收后，再以独立总体设计／实施路线图处理这些事项。
