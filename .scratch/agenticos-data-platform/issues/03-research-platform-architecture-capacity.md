# 调研 AgenticOS 承载数据中台的架构能力

Type: research
Status: resolved
Claimed by: background research agent
Parent: ../map.md
Blocked by: none

## Question

基于 `frontend/` 中的 AgenticOS 前端源码、Playwright 真实系统证据、数据服务原型、领域文档和 ADR，评估 AgenticOS 是否具备建设数据中台的架构基础。

按数据资产、数据工程、数据治理、数据服务四个产品域，以及租户与身份权限、系统配置、工作流、统一网关、Agent／MCP／Skill 能力、运行时、监控、审计和扩展机制等公共底座能力建立矩阵；每项标记为“已具备、可扩展、缺失、仅前端可见且后端未证实”，给出一手证据、关键耦合、能力缺口和对总体架构的影响。必须区分产品表面存在、前端接口契约存在与后端架构已经证实。

同时使用火山引擎 DataLeap 与阿里云 DataWorks 的官方资料建立参考能力框架，比较产品域覆盖和公共底座分层；只把它们作为能力范围与架构分层参考，不把竞品实现直接当作本项目目标架构。

## Answer

已完成调研，报告见 [AgenticOS 承载数据中台的架构能力评估](../../../docs/research/agenticos-data-platform-architecture-capacity.md)。

核心结论：当前 AgenticOS 已具备可复用的登录认证、组织角色与菜单权限、系统配置、Agent、系统监控和审计底座，但不足以直接承载生产级数据中台。资产与治理能力主要停留在前端页面和 API 契约，数据工程缺少批流任务开发、DAG／调度实例、开发生产隔离、发布管控、计算引擎与资源组等核心内核；租户／工作空间隔离和统一网关控制面也没有得到实现证据。

目标架构有条件可行：保留 AgenticOS 为公共底座，补齐统一隔离与分层配置，在其上新增独立的数据平台控制面和执行面，并让平台系统监控、数据任务运维、数据服务运行监控共享遥测设施但保持不同职责。报告已按四个产品域和公共底座逐项分级，并严格区分真实 HTTP 运行证据、前端契约、决策与原型。
