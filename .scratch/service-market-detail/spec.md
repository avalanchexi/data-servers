# 服务集市七类详情页规格

## 目标

在现有 `asset-service-prototype.html` 中，以统一的 API 式详情壳承载 API、数据流、Agent、MCP、模型、Skill、Worker 七类服务详情。页面服务于数据消费方与管理者，首要任务是解释外部人员如何通过数据应用使用、订阅、装配或提交服务。

## 统一页面结构

- 返回入口、服务名称、类型、状态、描述、领域、标签。
- 静态摘要：契约或资产形态、当前版本、接入方式、可用状态与更新时间。
- 左侧为类型专属文档页签；右侧为固定宽度接入指引、静态示例和治理提示。
- 支持页签键盘切换、复制示例、查看历史版本、折叠说明。
- 支持 `loading`、`error`、`no-permission`、`missing` 状态，由组件 API 触发，不增加演示控件。

## 七类信息架构

| 类型 | 左侧页签 | 右侧主任务 |
| --- | --- | --- |
| API | 概览、接口文档、版本记录 | 获取地址、认证占位符、请求示例 |
| 数据流 | 概览、消息契约、消费语义、版本记录 | 获取 Topic、消费者配置、订阅示例 |
| Agent | 概览、能力与依赖、调用契约、版本记录 | 创建会话、理解事件与依赖 |
| MCP | 概览、工具目录、连接配置、版本记录 | 区分 Agent 装配与外部客户端连接 |
| 模型 | 概览、模型能力、输入输出、评估指标、版本记录 | 提交推理、理解静态离线指标 |
| Skill | 概览、Skill 指令、文件与依赖、版本记录 | 装配到 Agent，不表现为独立 RPC |
| Worker | 概览、任务契约、调度与恢复、版本记录 | 提交异步任务并查询状态 |

## 明确边界

- 保留现有 18 个目录实例；同类型共享一套详情组件结构，实例值随服务变化。
- 不提供申请、注册、收藏、排序、逻辑表、在线调试、SDK 下载、凭证签发和真实请求。
- 示例仅使用占位地址及 `${ACCESS_TOKEN}` 等占位凭证；真实接入信息来自数据应用。
- 不展示动态性能监控指标；仅保留静态接入约束、可用状态、模型离线评估、Skill 兼容与安全扫描、版本及更新时间。
- 历史版本仅供查看；详情页不提供回滚或回归机制，回滚属于开发平面。
- DataLeap、阿里百炼、HiMarket 与协议文档仅作为信息架构证据，不在页面中露出竞品品牌。

## 组件接口

- `openMarketDetail(serviceId)`：打开详情。
- `closeMarketDetail()`：返回目录。
- `setMarketDetailState(state)`：设置 `ready/loading/error/no-permission/missing`。
- `getState()`：包含当前服务、详情页签、查看版本及详情状态。

## 验收

- 七种类型均可打开，默认落在各自“概览”。
- 各类型页签、字段、示例和术语相互区分。
- 页面与现有 AgenticOS 原型的字号、颜色、圆角、边框和间距一致。
- 1440×900 下无非预期横向滚动，右侧接入卡片保持清晰。
- 设计系统校验、脚本语法检查和本地交互检查通过。
