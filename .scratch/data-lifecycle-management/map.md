# 数据生存周期管理产品需求蓝图决策地图

Label: wayfinder:map

## Destination

形成一套可交给产品设计与研发继续细化的中文《数据生命周期管理产品需求蓝图》决策集：以 GB/T 36073—2025 DCMM 4 级“数据生存周期”为主轴，说明管理要求、竞品能力、治理对象与状态、平台／组织职责、功能架构、量化指标、证据闭环和分期边界；进入详细 PRD 前，不再遗留会实质改变产品范围或核心模型的未决问题。

## Notes

- 产品模块暂称“数据生命周期管理”；标准对标和能力矩阵严格使用 DCMM 正式术语“数据生存周期”，两者不得混写成同一概念。
- 本地图携带事实调研并输出到 `docs/research/`，但只解决产品决策，不编写页面级 PRD、视觉原型或生产实现。
- DCMM 目标沿用仓库既有研究，按 4 级“量化管理级”评估；每项要求必须区分平台可支撑能力、AgenticOS 公共底座／其他产品域能力、组织制度与外部证据。
- 国内竞品以阿里云 Dataphin／DataWorks、火山引擎 DataLeap、华为云 DataArts Studio 及当前东方金信参考原型为主；既有数据服务调研只作为局部证据，必须补查完整数据治理产品能力。
- 开源竞品补充 1–2 个 GitHub 高关注度项目；选择依据为当前社区关注度、官方资料完整度、生命周期治理相关性和与国内竞品的互补性，不以 Star 数单独决定。
- 事实调研使用 `$research`，只以标准原文、官方文档、官方仓库、源代码和本地一手材料支持结论；搜索摘要与第三方文章只能用于定位。
- 每次处理 `grilling` 工单时必须使用 `$grilling` 与 `$domain-modeling`；术语确认后即时更新 [`CONTEXT.md`](../../CONTEXT.md)。
- 领域架构沿用“数据中台应用层—数据平台控制面—数据执行与适配层—AgenticOS 公共底座”的既有边界，不把存储、计算、调度或网关基础设施管理并入生命周期产品。
- 所有对比都区分“产品明确提供”“官方资料可推断”“本项目建议”和“公开资料未证实”，不得把竞品页面名称直接当作本项目需求。

## Not yet specified

- 面向特定行业、法规和业务域的保留期限模板、法务保全条件及例外策略；需先明确通用对象、状态与策略模型，再判断哪些可配置为行业模板。
- “统一生命周期驾驶舱”与数据资产、数据工程、数据治理、数据服务既有页面之间的最终信息架构；需先完成能力归属与竞品采纳决策。
- AI 自动识别低价值数据、退役建议、需求查验和符合性检查的具体输入、置信度、人工复核与责任边界；需先明确可获得的元数据、使用、成本、质量和风险证据。

## Out of scope

- DCMM 认证申报、评估机构选择、组织制度文件编写、岗位设立、行业／国家标准制定等组织实施工作。
- 页面级字段、线框图、高保真原型、视觉设计系统和前端实现。
- 存储介质选型、冷热分层引擎、备份恢复、底层归档搬迁、物理销毁、计算与调度集群运维的具体实现。
- 生产数据库 Schema、API 契约、事件总线、适配器协议、部署拓扑和项目排期估算。
- 对竞品进行购买、开通租户或执行写操作；无法由公开官方资料验证的私有控制台行为不作为事实。
