# 确定设置模块的策略与字段边界

Type: grilling
Status: resolved
Parent: ../map.md
Blocked by: none

## Question

在“确定运行管理与设置的首版原型优先级”已经确定的页面深度下，租户信息、环境管理、服务类型、凭证与密钥策略、网关适配器分别需要哪些代表性可编辑项、只读状态和风险操作，同时避免把服务级配额、网关运行配置或平台级密钥生命周期错误放入设置？

## Answer

设置保留为数据服务域内面向管理者的二级功能，采用一张极简页面，只承载服务于域内各业务功能的必要共用配置。页面包含“集市产品类型”和“认证与密钥策略”两个区块；租户信息、环境管理、网关适配器、系统设置和基础设施运维均不进入。

### 集市产品类型

- 平台提供 Agent、MCP、模型、Skill、Worker、API、数据流、逻辑表等受支持类型及固定的运行语义和配置结构。
- 管理者只维护展示名称、说明、排序和对外呈现状态；业务上的新增和删除分别表达启用和停用对外呈现，不创建或物理删除类型。
- 停用只隐藏服务集市中的类型和新发现入口，不阻止创建或注册，也不影响既有产品、授权和调用；逻辑表标记为不可直接调用的资产类型。
- 展示信息修改保存后立即生效并记录审计；停用前展示受影响产品数量并二次确认，不进入审批。

### 认证与密钥策略

- 采用“数据安全底线 → 数据服务域默认值与上限 → 数据应用实际配置 → 统一网关执行投影”的分层。
- 认证方式和 Key 有效期使用公共策略；可调用产品类型可以分别覆盖请求并发和周期数据传输总量，逻辑表不参与。
- 并发和流量额度以数据应用为主体，同一应用的全部凭据共享额度；实时网络带宽和密钥生成、明文查看、保管、轮换操作不在设置中管理。
- 设置修改只进行影响预览、必要的二次确认和审计，不单独审批；数据应用的实际调整仍通过应用版本审批和发版。
- 收紧限制如果会使运行数据应用不合规，则阻止保存并列出受影响对象，必须先通过应用新版本完成调整；数据安全域的紧急强制限制走独立治理路径。
