## Comments

- 2026-08-27：用户确认本议题中的“数据服务层级”指完整平台内的一级“数据服务域”，与数据治理、数据安全等产品域并列；数据服务域内部包含工作台、服务集市、数据应用、应用与授权、审批中心、运行管理、设置七项功能，并非单个数据服务产品的设置。
- 2026-08-27：确认采用严格纳入门槛：设置只承载数据服务域特有、跨服务复用、确需配置且不更适合归属其他模块的对象或规则。设置以管理者为主要使用者，页面复杂度与设计深度均可精简；具体页面数量与旧五项菜单的去留留待后续轮次确认。
- 2026-08-27：用户确认旧五项全部移出设置：租户信息归系统上下文；逻辑环境由外部平台提供，数据服务只引用；产品类型是固定平台能力；认证与密钥策略归数据安全域，数据服务只显示生效规则；网关运行映射归运行管理，实例接入与连接维护归平台运维。
- 2026-08-27：用户随后明确设置仍需作为数据服务域第七项功能保留，主要为域内各业务功能提供必要共用配置；采用一张极简页面，“业务设置”是统称，当前包含产品类型、认证与密钥策略两组。本结论覆盖上一条中将产品类型、认证与密钥策略移出的决定；租户信息、环境管理和网关适配器仍保持移出。
- 2026-08-27：用户进一步澄清，原称“产品类型”的对象面向通过 API 形式使用 Agent、MCP、Skill、Worker 等能力的外部系统；混合场景中以 Agent 为主，因为 Agent 可能在包含数据和工具的沙箱运行。该分类究竟属于外部系统还是数据应用，以及如何与一项外部消费场景对应一个数据应用的既有边界兼容，仍需确认。
- 2026-08-27：用户认可域级默认值和上限、数据应用在允许范围内配置的方向，并将原“认证与密钥策略”扩展为数据应用对外服务策略，除认证方式和 Key 有效期外还可能包含请求并发、数据流量等限制；正式名称和与运行管理的边界仍需确认。
