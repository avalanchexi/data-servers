# 确定运行管理与设置的首版原型优先级

Type: grilling
Status: resolved
Parent: ../map.md
Blocked by: 21

## Question

面向第一版单 HTML 高保真原型，对“运行管理”和“设置”两个一级功能模块的二级菜单及主要功能点进行分级，分别判断产品重要性、建设优先级和原型呈现深度；高重要性、基础性能力需要设计，平台级告警、日志、审计、工作流引擎、密钥管理等能力暂不进入原型，同时保留核心业务闭环所需的状态投影。

## Answer

已形成并确认[运行管理与设置首版原型优先级分析](../../../docs/runtime-settings-prototype-priority.md)。

分级结论如下：

1. 产品重要性与原型建设优先级分开判断。P0 用于验证核心设计方向，P1 设计代表性页面，P2 只在业务场景中保留引用或状态，P3 保留菜单和导航入口但不设计实际功能页。
2. P0 不采用生产级深度。每个 P0 功能组只需要一个主页面、一个代表性详情和一条核心交互路径，不穷举全部字段、异常、状态和厂商差异。
3. 运行管理的网关概览、注册与路由、策略管理、配置发布为 P0；运行监控为 P1；相邻安全引用为 P2；异常事件、审计日志和调用日志为 P3。
4. 设置的环境管理、网关适配器为 P0；租户信息、服务类型、凭证与密钥策略概览为 P1；自定义服务类型为 P2；基础设施参数为 P3。
5. 运行管理和设置的所有二级菜单、目录及导航入口均保留。P3 菜单进入统一范围说明页，不以隐藏、空白页面或无响应表达。
6. 凭证与密钥策略保留菜单并设计简单概览页，展示默认认证方式、允许方式、Key 策略摘要和平台入口；不设计密钥生成、明文查看、保管和轮换。
7. 异常事件不设计独立业务页面，但网关概览、路由、后端和配置发布必须显示相关异常状态与失败原因；运行监控保留 API 与 AI 聚合指标，不包含日志、Trace 和告警规则。
8. 告警、日志、审计、工作流和密钥管理均假设为已存在的平台能力。凡 P0、P1 场景依赖这些能力，必须在场景中细化必要状态、引用、结果和导航入口，但不建设平台能力本身。
