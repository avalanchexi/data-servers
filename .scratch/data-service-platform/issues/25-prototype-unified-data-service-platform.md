# 验证数据服务平台统一原型

Type: prototype
Status: resolved
Parent: ../map.md

## Question

将 AI 服务开发、数据应用、运行管理和设置合并到同一个桌面 Web 原型后，哪一种统一页面壳层最能保持模块边界清楚、组件规范一致，并正确区分弹窗、只读抽屉和复杂详情页？

## Answer

采用单一共享壳层直接合并，不再制作 A／B／C 变体。一级目录固定为“服务集市、数据应用、服务开发、审批中心、运行管理、设置”，默认入口为服务集市；三个已验收来源原型的现有运行内容完整保留，仅统一目录与模块切换。服务集市和审批中心暂显示“协作页面待接入”，不补画尚未验收的业务流程。

新增和修改使用居中弹窗；简短只读信息和详情继续使用右侧抽屉；信息量大或包含多段连续任务的对象沿用独立详情页。合并结果为 `prototypes/data-service-platform-prototype.html`，可离线直接运行。
