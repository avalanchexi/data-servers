# 调研 API 服务三种开发方式

Type: research
Status: resolved
Parent: ../map.md
Blocked by: none

## Question

基于 DataLeap 等官方一手资料，传统开发、低代码开发和 Coding Agent 辅助开发应分别包含哪些输入、编辑、校验、测试、版本和上线环节？三种入口哪些部分应复用同一服务草稿和生命周期，哪些交互必须保持差异？

## Answer

研究确认：传统开发、低代码开发和 Coding Agent 应作为三种创作入口，而不是三种 API 产品或三套生命周期。三者统一产出同一种 API 服务草稿、OpenAPI 契约、测试证据、不可变服务版本和上线申请，并共用授权、统一网关、服务集市和运行管理。

- 传统开发以普通 SQL／Dynamic SQL 为实现表达，保留代码编辑、参数解析、Dry Run 和查询日志；消费者输入优先使用类型化参数绑定。
- 低代码开发首期采用单张 ADS 逻辑表和结构化查询模型，通过条件、字段、排序和分页生成 SQL 与契约；低代码转 SQL 建议单向转换。
- Coding Agent 没有与本项目完全对应的官方数据服务产品依据，应建模为对 SQL 或低代码草稿提出 Patch 的辅助入口。它只能在开发者已有权限范围内工作，生成内容必须逐项人审、真实测试并由开发者亲自提交，不能自动取得权限、审批或上线。
- 三种入口只在编辑器、入口级校验、转换和 Agent 生成溯源上保持差异；来源权限、公共校验、测试、版本、生产审核及上线流程必须一致。
