# 确定统一网关运行配置与发布边界

Type: grilling
Status: resolved
Parent: ../map.md
Blocked by: 20

## Question

基于《调研统一网关运行管理的必要配置》的事实结论，确定数据服务平台首期实际管理哪些统一网关产品级配置、哪些只读展示、哪些归入设置或基础设施系统；同时确认配置发布是否独立成二级模块、生产配置变更审批、紧急停流、简单灰度、AI 多模型路由、内容采样、WAF 引用以及配置漂移的产品规则。

## Answer

现有“运行管理＋设置”结构适用于微服务和云原生部署，但产品边界限定为厂商中立的数据服务与统一网关控制面，不复刻 Kubernetes、服务网格或具体网关控制台。

1. **产品级可写配置**：运行管理负责入口引用、服务路由、后端池、健康策略、认证投影、流量与安全策略、AI 路由与安全策略，以及有版本的配置发布。
2. **只读运行信息与受控操作**：展示网关连接和数据面健康、实际配置、路由下发、后端健康、指标、调用日志、追踪入口、异常、漂移和审计；允许测试连接、刷新、重试、回滚及紧急停流等受控动作。
3. **设置归属**：设置仍只包含租户信息、环境管理、服务类型、凭证与密钥策略、网关适配器。环境是逻辑环境；适配器保存实例连接引用、能力声明和环境绑定，不暴露 Secret 原文。
4. **基础设施边界**：Kubernetes 集群、Namespace、Pod、副本、CRD、服务网格、网关节点、密钥原文和可观测基础设施由外部基础设施系统管理。统一网关管理外部消费的南北向流量，不管理微服务东西向流量。
5. **二级信息架构**：运行管理采用网关概览、注册与路由、策略管理、配置发布、运行监控、异常事件、审计日志七个二级模块。“配置发布”独立呈现，不并入路由页面。
6. **审批规则**：生产配置变更按风险分级；高风险变更必须审批，低风险变更在校验通过后可自动执行。所有变更都形成配置发布、差异和审计记录。
7. **紧急停流**：管理者可在故障或安全事件下绕过普通事前审批，二次确认后立即停流；必须完整审计并事后补充事件和审批关联。
8. **首期流量能力**：支持当前版本与候选版本的简单权重灰度；AI 逻辑模型支持多个物理目标的权重路由和优先级降级。复杂金丝雀及成本、延迟、语义选模暂不纳入。
9. **内容与 WAF**：Prompt 和响应正文默认不采样，仅在指定服务和环境经过单独审批、脱敏后限时开放；WAF 只管理外部策略引用、绑定范围和生效状态，不建设规则编辑器。
10. **配置漂移**：不自动覆盖平台或网关。平台展示结构化差异，由管理者选择通过新配置发布覆盖实际状态，或接纳实际状态成为新的期望版本；两种动作都必须审计。

配置发布状态采用：`草稿 → 校验中 → 待审批或待发布 → 发布中 → 已生效`，并允许进入校验失败、已驳回、已取消、部分失败或发布失败；回滚创建新的配置发布记录。
