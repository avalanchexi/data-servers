# 数据服务平台 DCMM 4 级系统支撑能力分析

> 文档性质：产品与系统支撑能力分析，不是正式 DCMM 评估报告或达级声明。
> 标准范围：GB/T 36073—2025 第 5.2.4 条 5 项通用特征，以及第 6—14 章 33 个能力项的 114 条四级要求，共 119 个原子要求。
> 仓库基线：2026-08-28 当前工作区；仓库外系统、制度、人员活动和生产运行不作存在性推定。

## 0. 结论

**当前仓库不能证明所属组织达到 DCMM 4 级，也不能证明数据服务平台已经具备生产级 DCMM 4 级支撑能力。**

本报告先分析 DCMM 4 级对**整体数据中台及公共底座**的系统支撑要求，再映射到最终确认的五项数据服务业务能力：**服务集市、数据应用、服务开发、运行管理、设置**。

119 个要求按主责任互斥分类如下：

| 类别                     | 定义                                                                                   |          数量 |           占比 |
| ------------------------ | -------------------------------------------------------------------------------------- | ------------: | -------------: |
| A 系统直接实现/控制      | 主要动作能由系统执行、阻断、计算或追踪，并可通过功能、配置、日志和测试直接验收。       |            26 |          21.8% |
| B 系统提供支撑、组织负责 | 系统提供数据、指标、模型、流程、报告和证据；目标、决策、周期评价和持续改进由组织负责。 |            54 |          45.4% |
| C 组织/外部活动          | 组织设置、人才文化、外部评价/审计、标准化活动等，系统最多保管材料。                    |            39 |          32.8% |
| **合计**           | `5 + 114`                                                                            | **119** | **100%** |

A 类功能上线不等于组织达级；B 类页面或报表存在不等于组织已经运行并持续改进；C 类不能用产品证据替代。当前路线图明确排除生产后端、真实消息代理和正式系统建设（`.scratch/data-service-platform/map.md:41-48`），运行指标研究也明确所有数值为离线示例且未接生产采集（`docs/research/runtime-instance-metrics.md:7-9,77-79`）。原型中的指标、审批、审计和“上线”状态均不是运行证据。

## 1. 口径与证据等级

### 1.1 当前与目标分列

| 维度       | 规则                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 当前可证明 | 只依据仓库事实；文档只证明约定，原型只证明交互设计，原型测试只证明内联脚本满足测试契约。       |
| 目标覆盖   | 判断领域约定、ADR、研究和已确认议题是否定义了系统应承担的能力；目标明确仍不表示已实施。        |
| 组织证据   | 制度、职责、真实周期数据、签批记录、正式报告、内外审材料和标准化活动证明；仓库没有时不得推定。 |

### 1.2 证据等级

| 等级 | 名称          | 判定规则                                                                                |
| ---- | ------------- | --------------------------------------------------------------------------------------- |
| E3   | 生产实现/运行 | 后端、持久化模型、接口、真实采集/执行适配器、部署、集成测试和连续运行记录。当前未发现。 |
| E2   | 原型          | 离线 HTML/JavaScript 及原型回归测试，只证明信息架构、状态和交互。                       |
| E1   | 文档          | `CONTEXT.md`、ADR、研究、议题和设计规范，只证明目标、术语或边界。                     |
| E0   | 无直接证据    | 未发现与要求对象直接对应的仓库事实。                                                    |

### 1.3 A/B/C 边界

- A/B/C 是条款主责任的互斥分类，不是实现状态或成熟度得分。
- B 类通常包含“设定指标、定期评价、形成报告、持续改进、效果/收益”等管理判断。
- C 类包括业务范围、组织岗位、文化、外部机构活动，以及参与国家标准和主导行业标准。
- `12.1.3` 虽要求 AI 合规风险分析，但法规适用和合规结论由组织负责，归 B；`14.3.3` 虽要求 AI 评价开放效果，但效果和影响由组织确认，归 B。

### 2.5 强制共性模式

1. **量化指标 → 监测/评价 → 报告 → 改进**：需保存指标版本、分母、窗口、来源、基线、目标、责任人、问题和复测，不能只展示数字。
2. **AI → 人工治理 → 效果证明**：模型/规则版本、输入授权、输出、解释、人工决定、执行结果和基线对照必须成链。
3. **标准化活动是组织硬边界**：第 7—14 章 30 个能力项均有标准参与末条，加 `5.2.4e` 共 31 条 C 类要求。
4. **定期、持续、提升需要跨周期证据**：静态截图、固定样例和一次报告不能证明趋势。
5. **成本、价值、风险需共同量化**：允许定量或分级证据，不要求全部精确货币化，但需有口径、来源和批准。
6. **统一对象链**：租户、组织、人员、资产、应用、服务、固定版本、权限、模型/规则、运行结果、评价、问题、整改和审计需能关联。

## 4. 平台公共基础能力层

### 4.1 分工与契约

```text
平台公共底座
├─ 执行：身份、权限、流程、密钥/证书、审计写入、通知、运维采集
└─ 存储：组织/租户、身份策略、流程、凭据元数据、证据、事件、可观测数据
        ↑ 版本化调用/事件契约
数据服务五项能力
├─ 维护：服务、应用、版本、业务规则、对象关联、指标口径

```

### 6.3 14.4.3 AI 价值机制与可靠数据基础（A；正式决定属组织）

> “采用人工智能技术，构建数据产品价格调控机制，为数据产品定价提供可靠的数据基础。”

本评估**不把该条误实现为数据服务中的对外交易定价页面**。数据服务优先提供可追溯的价值、成本、风险、质量和稳定性数据，以 AI 做归集、异常识别、相似服务比较、价值分级和建议；正式价格调控、财务口径或交易决定由资产运营、财务或经营组织负责。

| 维度          | 分析                                                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 系统责任      | 归集成本、使用、复用、质量、风险、SLA、支持投入和效果；AI 提供价值分级/建议、解释、版本、人工复核和回测。                                                |
| 当前证据/覆盖 | 有 AI 辅助开发和运行样例，但无成本、价值、价格、服务方或效果数据模型；相邻 AI 原型不能替代本条。**当前缺失**。                                     |
| 目标/缺口     | **目标缺失/外部协同**：五项可提供可靠数据基础，正式价格机制不归数据服务单独负责。                                                                  |
| 价值口径      | 重点为效率提升、成本节约、风险规避、服务稳定和复用；使用/消费效果仅辅助，不强制全部精确货币化。                                                          |
| 组织与验收    | 业务/资产/财务批准口径和正式决定；需数据来源、AI 版本/解释、人工决定、回测，以及节约人天、周期缩短、重复开发减少、风险事件避免、SLA/恢复改善等真实样本。 |

## 7. 价值结果的适度量化

DCMM 4 级要求量化管理，不等于全部价值必须折算金额。

| 类型      | 可接受证据                                                  | 参考增强项，不一律强制       |
| --------- | ----------------------------------------------------------- | ---------------------------- |
| 效率      | 节约人天、自动化比例、审批/开发/交付周期缩短、处理量提升    | 严格对照实验、长期因果归因   |
| 成本      | 重复开发减少、闲置服务下线、资源/支持投入下降、复用替代次数 | 精确全成本分摊、财务确认金额 |
| 风险      | 越权/泄露/错误发布阻断数、严重度下降、整改时长              | 对未发生事件精确货币估值     |
| 稳定      | SLA/SLO、成功率、错误预算、MTTR、复发率、回滚改善           | 每次改善折算收入             |
| 应用/消费 | 活跃应用、采用、满意度、复用、服务方评分、业务结果分级      | 只用调用量推断价值           |

最低要求是口径、对象、窗口、基线、来源、责任人和结论可追溯；基线、归因模型和金额可作为可信度增强项，证据不足时必须披露限制。
