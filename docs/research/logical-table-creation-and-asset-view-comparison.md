# 阿里云、华为云、火山引擎“逻辑表”创建管理与资产展示对比

> 调研对象：阿里云 Dataphin、华为云 DataArts Studio、火山引擎 DataLeap（OneService）  
> 官网复核日期：2026-08-31（Asia/Shanghai）  
> 证据范围：厂商官网帮助中心、官方 API 文档、帮助中心内嵌的官方产品截图。搜索结果和仓库既有材料仅用于定位，未作为结论证据。  
> 调研限制：本轮没有三家产品的付费租户权限；“查看原网站”是指重新打开官方帮助页、核对正文、更新时间与官方产品截图，不等同于登录实际租户完成生产创建。

## 1. 结论先行

三家都使用“逻辑”概念，但对象不处于同一层级，不能把三套流程拼成一个通用“逻辑表生命周期”。

| 产品 | 官网正式对象 | 对象实质 | 创建后的主要去向 | 与本仓库“逻辑表”的接近点 |
|---|---|---|---|---|
| 阿里云 Dataphin | 维度、事实、汇总逻辑表；资产清单另含标签逻辑表 | 数仓规范建模对象，同时承载计算、质量、调度和生产任务 | 提交/发布、运维、治理资产清单、上架后进入资产目录，也可作为 API 来源 | 治理字段、业务语义、资产目录与研发对象的衔接最值得参考 |
| 华为云 DataArts Studio | **逻辑实体（即逻辑表）** | 业务语义模型中的实体定义，不等同于物理表 | 审批发布后同步为业务资产；或转换为物理模型 | 业务资产与技术资产分视角、发布与资产同步分状态最值得参考 |
| 火山引擎 DataLeap | 数据服务逻辑表 | 物理表到 API 之间的虚拟映射与字段契约 | 保存后授权项目、开发 API、在逻辑表集市跨项目发现和申请权限 | 与本仓库“由 ADS 资产映射、供服务开发引用、不可直接调用”的定位最接近 |

官方依据：Dataphin 将维度/事实/汇总逻辑表放在规范建模中，并在资产清单提供逻辑表详情；DataArts 的官方原文明确“逻辑实体即逻辑表”；DataLeap 将逻辑表定义为逻辑建模产生的虚拟表、物理表映射。[Dataphin 规范建模](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/research-and-development-of-data-modeling/)、[DataArts 逻辑模型](https://support.huaweicloud.com/intl/zh-cn/usermanual-dataartsstudio/dataartsstudio_01_0540.html)、[DataLeap 基本概念](https://docs.volcengine.com/docs/6260/127705?lang=zh)

最核心的横向判断是：

1. **Dataphin 的“逻辑表”最重**：从业务对象、字段、计算逻辑一直覆盖质量、调度、发布和运维。
2. **DataArts 的“逻辑表”最偏业务模型**：逻辑实体发布后可成为业务资产，也可进一步生成物理模型；逻辑实体与物理表必须区分。
3. **DataLeap 的“逻辑表”最偏服务契约**：它映射已有物理表，管理字段转换、查询约束、授权、主备和 API 使用；公开文档没有给出逻辑表自身的发布状态机。
4. **三家都把“能看到资产”和“能读取数据”区分开**。资产可见、模型编辑/发布、底层数据权限、下游服务授权不应合并为一个权限。

## 2. 证据标记和比较口径

- **官网正文**：官方帮助页正文明确说明，可作为公开能力证据。
- **页面观察**：官方帮助页内嵌产品截图可见，但正文未逐字段解释；可能随区域、版本和租户配置变化。
- **官方 API**：官方接口模型中存在；只证明后端/接口数据结构，不能自动等同于当前 Web UI 必然逐项展示。
- **推断**：由多项官方事实组合得出的产品结构理解，不是厂商原话。
- **公开资料未证实**：截至复核日，官网公开材料不足，不能按确定能力写入需求。

数据资产页统一按两层盘点：

1. **列表/搜索层**：用户如何发现逻辑表，以及卡片或表格默认显示什么。
2. **详情层**：表级信息、字段、来源映射、治理、血缘、质量、预览、权限、版本/变更、使用影响。

## 3. 阿里云 Dataphin

### 3.1 对象与入口

Dataphin 的正式建模对象包括普通/层级/枚举/虚拟维度逻辑表，事件/快照/流程事实逻辑表，以及汇总逻辑表。当前资产清单还把标签逻辑表列为逻辑表类型，但公开的当前全托管文档没有给出与前三类等价的标签逻辑表新建向导。[维度逻辑表](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/specification-defines-dimension/)、[逻辑表和字段详情](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/logical-tables-and-fields-details)

维度和事实逻辑表的主要入口是 `研发 > 数据研发 > 规范建模`；汇总逻辑表入口为 `研发 > 数据开发 > 规范建模 > 汇总逻辑表`。

### 3.2 创建到使用的完整过程

```text
业务实体/业务活动
  → 新建维度或事实逻辑表
  → 表结构与字段治理
  → 关联维度、来源和字段计算
  → 字段约束、调度、依赖、参数、运行配置
  → 保存并提交
  → Dev-Prod：待发布对象 → 审批/校验 → 发布
     Basic：提交后直接进入生产
  → 运维中心管理任务与实例
  → 治理 > 资产清单
  → 完善准资产信息并上架
  → 资产 > 资产目录
  → 查表/分析，或在数据服务中创建逻辑表 API
```

#### 创建

1. 先准备业务对象：维度表依赖业务实体，事实表依赖业务活动；汇总表依赖统计粒度及已上线逻辑表。
2. 新建表级对象，填写业务对象/业务活动、表类型、数据板块、主题域、数据时效、逻辑表名、中文名称、描述。
3. 配置字段：字段名、说明、类型、主键/分区/属性类别、关联维度、字段标准、唯一/非空约束、分类分级、备注。
4. 配置来源与计算：来源可为物理表、自定义 SQL 或逻辑表；设置来源对象、别名、描述、过滤条件、主键对应字段和字段计算表达式。
5. 配置质量、调度和运行：规则强度、数据延迟、调度属性、上游依赖、参数、资源/运行配置。
6. 保存并提交。系统检查结构、计算、依赖和参数，并解析开发环境血缘。
7. Dev-Prod 模式进入待发布列表，处理依赖、审批和发布校验；发布时解析生产环境血缘。Basic 模式提交后直接进入生产。[新建普通维度逻辑表](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/create-a-logical-dimension-table)、[新建事实逻辑表](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/create-a-logical-fact-table)、[管理发布任务](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/manage-publishing-tasks-1)

汇总逻辑表有两条单独路径：相同统计粒度和时效的派生指标自动汇聚，或先创建无指标的空汇总表，再添加/挂接指标。[新建汇总逻辑表](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/create-a-logical-summary-table)

#### 管理

- 研发列表显示逻辑表名、主题域/业务实体、数据时效、开发状态、最近提交状态、当前锁定人、开发负责人。
- 支持打开、获取锁、转交开发负责人、发布、去运维、下线、删除、下线并删除；存在下游依赖时相关操作受阻。
- 批量支持锁定、提交、下线、标签、负责人、运行/参数/依赖配置。
- 基本信息还包括表类型、业务对象、板块、主题域、时效、中文名、描述、表负责人、开发负责人、运维负责人和标签；部分关键字段创建后不可修改。
- 可查看关联逻辑表、输入表、依赖对象和下游任务；运维侧支持补数据、生产链路和消费链路。[管理维度/事实逻辑表](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/manage-logical-dimension-fact-tables)、[查看及管理逻辑表相关对象](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/view-and-manage-logical-table-related-objects)

#### 使用

- 有权限时可生成 `SELECT`、在 Notebook 分析、预览数据；建模逻辑表支持表级或字段级查表权限，并可叠加行级规则。
- 已发布逻辑表可进入运维中心补数据并查看生产/消费链路。
- 数据服务支持基于维度、事实、汇总逻辑表以 SQL 或向导方式创建 API。SQL 模式的官方链路是：先保证逻辑表产数正确，再配置并发布同步任务，然后进入 `服务 > API开发 > API服务 > 新建API`，选择“逻辑表API-SQL模式（Dataphin表）”，选择板块与逻辑表、编写 SQL、解析并配置请求/返回参数，最后保存、测试、提交和发布 API。请求参数与返回参数必须来自同一张逻辑表。这里的提交/发布属于 API，不是逻辑表的第二次发布。[通过 SQL 模式创建 API（Dataphin 表）](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/sql-mode)、[创建 API](https://help.aliyun.com/zh/dataphin/fullmanaged/user-guide/create-api/)

## 4. 华为云 DataArts Studio

### 4.1 对象与入口

华为云对通用“逻辑表”的正式对象名是**逻辑实体**，官方直接说明“逻辑实体即逻辑表”。逻辑实体位于逻辑模型中，入口为 `DataArts Architecture（数据架构） > 数据调研 > 逻辑建模 > 逻辑模型`。它是业务语义对象，不是已落库的物理表。[逻辑模型](https://support.huaweicloud.com/intl/zh-cn/usermanual-dataartsstudio/dataartsstudio_01_0540.html)

DataArts 还存在维度建模中的事实逻辑表、维度表、汇总逻辑表等专用对象。本报告以官网明确“即逻辑表”的通用逻辑实体为主，不用维度建模对象代替它。

### 4.2 创建到使用的完整过程

```text
工作空间成员/审核人/功能项
  → 新建逻辑模型
  → 新建逻辑实体
  → 基本配置
  → 逻辑实体属性
  → 关系与映射
  → 发布并选择审核人
  → 全部审核人通过
  → 已发布
     ├─ 默认或手工同步 → DataArts Catalog 业务/逻辑资产
     └─ 转换物理模型 → 落库物理表 → 元数据采集 → 技术资产
```

#### 创建

1. 在工作空间准备审核人、主题、逻辑模型及模型设计功能项。
2. 在逻辑模型的逻辑实体管理页单击“新建”。
3. 配置“基本配置”：所属主题、编码、中文名称、表英文名称、父逻辑实体、标签、资产责任人、描述。
4. 配置“逻辑实体属性”：名称、英文名、编码、类型、数据标准、主键、分区、不为空、标签、密级、描述。
5. 配置实体关系：关系名、父/子逻辑实体、PK/FK 属性、双向基数、角色。
6. 配置映射：源/目标逻辑实体、JOIN 类型和属性、逻辑属性映射。
7. 单击“发布”、选择审核人；企业模式还要选开发或生产环境。
8. 多审核人必须全部通过，任一驳回即“已驳回”；审核意见在审核中心留痕。
9. 发布后，默认配置可把新逻辑实体同步到 DataArts Catalog；历史对象可手工补同步。[逻辑模型](https://support.huaweicloud.com/intl/zh-cn/usermanual-dataartsstudio/dataartsstudio_01_0540.html)、[审核中心](https://support.huaweicloud.com/intl/zh-cn/usermanual-dataartsstudio/dataartsstudio_01_0619.html)

#### 管理

- 同步：仅已发布逻辑实体可同步业务资产。
- 发布/批量发布：选择审核人，审核通过后发布。
- 下线：仅已发布对象可下线。
- 删除：仅草稿、已驳回、已下线对象可删除。
- 修改主题、标签、编辑和查看详情。
- 发布历史与版本对比、预览 SQL、导入/导出、数据库逆向。
- 可为属性关联质量规则；配置中心开启相应功能后，发布会生成质量作业。

#### 使用

逻辑实体有两条主要使用路径：

1. **业务资产路径**：发布/同步后进入 DataArts Catalog，供用户按业务对象、逻辑实体和业务属性检索、理解和治理。
2. **物理化路径**：逻辑模型转换为关系建模中的物理模型；选择数据连接、数据库、Schema/队列、全部或部分逻辑实体以及物理表更新方式。后续物理表才承载引擎查询、预览、技术血缘和底层权限。

公开官网没有证明“逻辑实体发布”会自动在数据库建表，也没有证明只对逻辑实体业务资产申请一次权限即可覆盖全部关联物理表。[数据架构概述](https://support.huaweicloud.com/usermanual-dataartsstudio/dataartsstudio_01_0601.html)、[访问权限管理流程](https://support.huaweicloud.com/usermanual-dataartsstudio/dataartsstudio_01_1151.html)

## 5. 火山引擎 DataLeap（OneService）

### 5.1 对象与入口

DataLeap 数据服务将逻辑表定义为“逻辑建模后产生的虚拟表”和“物理表的一个映射”，用于屏蔽底层存储、转换字段类型、规范命名和配置备份容灾。入口为 `DataLeap 租户控制台 > 数据服务 > 数据源 > 逻辑表`。[基本概念](https://docs.volcengine.com/docs/6260/127705?lang=zh)、[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)

### 5.2 创建到使用的完整过程

```text
创建数据源
  → 注册物理表
  → 创建逻辑表（同名 / 极简批量 / 标准单表）
  → 保存
  → 默认项目授权或授权管理
  → 项目内 API 开发
  → API 保存、测试、发布、调用

同一业务线跨项目：
逻辑表集市 → 搜索/详情 → 申请授权项目和用途 → 获权后预览探查或使用
```

#### 三条创建路径

1. **创建物理表时生成同名逻辑表**：在物理表基本信息确认阶段设置安全等级、是否创建同名逻辑表、存储目录。
2. **极简模式批量创建**：选择多张物理表，指定默认授权项目，可编辑逻辑表名称和存储路径。
3. **标准模式单表创建（官方推荐）**：选择 MySQL、ByteHouse、Doris 或 StarRocks 类型下已成功注册且当前用户为 Owner 的物理表；选择/治理字段，设置查询约束、默认项目、名称、目录、安全等级、描述和下游 API 使用管控，最后保存。[物理表管理](https://docs.volcengine.com/docs/6260/127698?lang=zh)、[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)

#### 管理

- 详情包括基础信息、字段信息、预览探查、授权管理、变更记录。
- 字段可修改名称、中文名、类型、描述、安全等级、主键信息、关联指标/维度。
- 可切换来源物理表并重新映射；支持手动、同名和同行映射。
- 可编辑默认授权项目、安全等级、描述、查询约束、标签、下游 API 管控。
- 支持搜索名称/ID/负责人/描述，按数据源类型、标签和负责人高级筛选。
- 支持转交负责人、移动目录、主备配置、版本回退和删除。
- 主备要求数据源类型相同、字段完全一致；启用备份表后实际流量切至备份表。
- 若已有 API 关联则不能删除逻辑表。

#### 使用

- 脚本式 API：可使用同源多张逻辑表，最多 10 张。
- 向导式标准模式：使用单张逻辑表，把请求参数形成 `WHERE` 字段、返回参数形成 `SELECT` 字段并生成 SQL。
- 原生式 API：圈选同源逻辑表，最多 5 张，由用户动态传入 SQL。
- API 的请求/返回参数可绑定逻辑表字段，随后进入 API 保存、测试和发布流程。[API 开发](https://docs.volcengine.com/docs/6260/127699?lang=zh)

2026 年版 API 开发还提供可直接选择数据源及数据表的向导式“便携式”模式。因此旧文档“API 必须使用逻辑表”的说法不再适用于所有当前 API 类型，只适用于逻辑表标准路径。

## 8. 对本仓库数据服务平台的可用结论

本仓库当前把逻辑表定义为“由 ADS 层数据资产映射形成、在服务集市可见、可被数据服务开发者引用、不可直接向数据应用提供 JDBC/SQL/HTTP 查询”的资产。这一定位不应照搬某一家，而应吸收三家的不同长处。

### 8.1 建议保留的产品边界

1. **逻辑表不是可调用服务。** 逻辑表详情可以提供预览/探查和“用于创建服务”的入口，但不进入 API、Agent 等可调用产品的上线状态机。DataLeap 的逻辑表/API 生命周期分离最接近这个边界。
2. **逻辑表定义不等于物理表。** 页面必须展示 ADS 来源资产与字段映射，不能把物理存储字段直接冒充逻辑定义。DataArts 的业务/技术资产分视角和 DataLeap 的来源映射可共同参考。
3. **资产可见、开发者数据权限、服务上线审批、数据应用运行权限四者分开。** 三家均提供了不同程度的分层证据，本仓库 `CONTEXT.md` 也已明确开发者数据权限不由服务自动继承。
4. **资产发现页与资产治理页分开。** Dataphin 的资产清单/资产目录差异说明：治理详情可以很深，但集市卡片只需展示支持发现和决策的摘要。

### 8.2 可用于原型的创建信息架构

以下是竞品证据支持下的本项目设计输入，不是三家官网的共同标准：

1. **来源选择**：所属租户/业务域、ADS 来源资产、来源环境、来源字段。
2. **基本信息**：逻辑表名称、展示名称、业务描述、主题/目录、负责人、标签。
3. **字段契约**：字段名/展示名、逻辑类型、来源字段、描述、主键/分区标识、是否可为空。
4. **治理属性**：数据标准、分类分级/密级、字段可见性、质量规则或质量状态引用。
5. **使用约束**：允许作为查询条件/返回字段、必选查询约束、数据时效、预览限制。
6. **权限与可见性**：开发者可见范围、默认授权范围、申请状态；不在此处授予数据应用运行权限。
7. **保存与影响检查**：保存草稿/生效动作、来源或字段变更的下游服务影响、存在引用时的删除阻断、版本与变更记录。

### 8.3 可用于原型的资产列表与详情字段

**服务集市列表建议最小集合：**名称/展示名、逻辑表类型标识、业务域/主题/目录、来源类型、负责人、密级、标签、字段数、数据时效/最近更新时间、开发者是否有权引用。

**详情建议按页签分组：**

- 概览：身份、归属、负责人、描述、标签、密级、时间；
- 字段与映射：逻辑字段、来源字段、类型转换、标准、分类分级；
- 来源与血缘：ADS 来源资产、上游链路、已引用该逻辑表的服务及版本；
- 质量与时效：质量状态、规则引用、数据更新时间/时效；
- 预览探查：受当前开发者权限约束的样例和查询；
- 权限：可见范围、开发者数据权限、申请记录；
- 版本与变更：字段/映射变更、责任人变更、影响分析和历史版本。

上述字段需再与本仓库现有原型逐项对照后才能成为最终需求；本报告只提供竞品证据和边界，不直接修改产品定义或原型。
