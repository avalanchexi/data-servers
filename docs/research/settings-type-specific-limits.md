# 设置页：类型限制、认证凭据策略调研与原型映射

日期：2026-08-27。对象：`prototypes/archive/2026-09-02/settings-page-prototype.html`。

## 结论与边界

按本轮浏览器批注，设置目录分为“集市产品类型”“认证与密钥策略”“类型专属限制”。认证方式及各自对应的凭据有效期、接受边界属于公共策略；七类可调用产品分别维护调用与执行限制，逻辑表不参与。

不能把所有类型都配置成“HTTP 并发 + GB/月”。模型需要 Token 计量；Agent、Skill、Worker 的执行语义由运行时理解；业务数据流的订阅与消息约束由订阅适配器执行。设置页维护的是域级上限，不是网关基础设施参数，也不表示已实现这些后端能力。

以下分开记录官方能力事实与本项目原型提案。全部数值是合成的评审示例，不是官方默认值、生产推荐值、压测结论或本项目已接入能力。

## 类型限制的官方资料与可确认事实

## 认证方式与凭据有效期

### 官方事实与原型选择

四项沿用领域文档的认证接入名称，但并非四种互斥的底层协议：OAuth 访问令牌可以采用 JWT 格式，mTLS 也可与 OAuth 配合。页面把它们作为接入配置档案，不将独立 JWT 档案重复套到 OAuth 令牌上；本轮不扩展组合策略编辑器。[OAuth 与 mTLS](https://www.rfc-editor.org/rfc/rfc8705.html)

| 接入方式 | 凭据对象与已确认事实 | 本轮原型字段及边界 |
| --- | --- | --- |
| OAuth 2.0 | 访问令牌由认证服务签发，`expires_in` 用秒表达寿命；Client Credentials 响应不应默认包含刷新令牌。[RFC 6749 §4.4.3](https://www.rfc-editor.org/rfc/rfc6749.html#section-4.4.3)、[§5.1](https://www.rfc-editor.org/rfc/rfc6749.html#section-5.1) | 按已确认的服务间 Client Credentials + Client Secret 场景演示。访问令牌默认／最长有效期以分钟配置，客户端密钥默认／最长有效期以天配置，二者独立。Client ID 不是密钥；本页不签发、刷新或轮换凭据，也不承诺修改外部认证服务。 |
| API Key | 凭据应尽可能设置适合其类型的有效期，消费方应验证仍有效；过期、轮换与吊销是不同生命周期事件。[OWASP 凭据生命周期](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html#27-secret-lifecycle) | 默认／最长有效期以天配置，不将现有示例天数当作行业要求。沿用项目约定：轮换使旧 Key 立即失效，无新旧并行期；轮换操作不放入本页。 |
| JWT | `exp` 决定到期时间，`iat` 表达签发时间，存在 `nbf` 时需遵守生效时间；通用 JWT 标准将这些声明列为可选项。[RFC 7519 §4.1](https://www.rfc-editor.org/rfc/rfc7519.html#section-4.1) | 独立 JWT 接入契约要求 `exp`、`iat`，检查 `exp > iat` 及 `exp − iat ≤ 最大可接受时长`，以分钟配置。这是项目安全约束，不是通用标准强制项；不能重写签名后的令牌。签名、签发方、受众及签名密钥轮换仍由认证适配层和签发方负责。 |
| mTLS | X.509 证书具有签名确定的 `notBefore` 和 `notAfter`，认证路径验证还涉及签名、有效区间和吊销状态。[RFC 5280 §4.1.2.5](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.1.2.5)、[§6.1.3](https://www.rfc-editor.org/rfc/rfc5280.html#section-6.1.3) | 以天配置“可接受证书最长有效期”，限定客户端叶证书总签发周期 `notAfter − notBefore`，不是剩余天数；当前时间仍须在证书自身有效区间内。TLS 适配层负责信任链、用途和吊销校验；本页不签发、续签、延长证书，不收集私钥。 |

### 示例值与联动约定

- OAuth 访问令牌：默认 60 分钟、最长 120 分钟；客户端密钥：默认 90 天、最长 180 天。
- API Key：默认 90 天、最长 180 天。原型保留原有数据安全域 365 天的**示例**上限，该数字不是标准通用要求。
- JWT：最大可接受令牌时长 60 分钟。mTLS：可接受证书最长有效期 365 天，初始未启用。
- 除原有 API Key 示例上限外，本轮不杜撰未确认的安全域硬上限；新字段仅校验正安全整数、同类默认值不超过最长值及运行应用影响。生产上限、支持能力与计量单位须由安全域和实际签发／认证适配层确认，未知时不能视为已支持。
- 默认认证方式保留在顶部；四种允许方式纵向排列。勾选展开对应字段，取消勾选收起并禁用该组，保留暂存输入供重新勾选；保存不校验、不提交未启用组的临时输入，保留其上次已保存策略。
- 默认选项只包含已勾选方式；取消当前默认后清空默认选择并提示重新选择，不静默换成其他方式。至少启用一种，且默认方式必须在启用集合中。
- 按实际凭据对象检查影响：经营分析助手使用 90 分钟令牌和 120 天客户端密钥，经营指标查询使用 120 天 API Key，实时订单订阅使用 30 分钟 JWT，均为合成校验样本。取消它们使用的认证方式、收紧对应最长值到样本配置以下都会阻止保存；不是拿 API Key 天数检查全部类型。
- 默认值仅服务于新配置，上限调整也不能改写已签发令牌、密钥或证书的到期时间。数据应用配置调整仍需版本审批与发版；认证服务和证书系统的实际签发、轮换及吊销不由本原型执行。

## 计量与生效约定（项目提案）

- 以当前租户中的数据应用为配额主体，同一应用全部凭据和同类型能力共享额度；不能按 API Key 分桶后导致轮换／多凭据放大额度。生产实现须使用认证后获得的可信应用标识，不接受消费方随意填入的标识。
- 不同类型使用独立维度。Agent 调用模型时，模型额度按底层推理请求计量；Agent 的步骤和工具次数是运行维度，不把同一推理 Token 在入口和子调用重复扣除。直接暴露给外部的 Skill 封装入口另遵循相应入口类型的约束。
- 月度配额按本项目业务自然月（Asia/Shanghai）计算；GB 为十进制字节量，KiB/MiB 为二进制大小。HTTP／订阅交付的请求及响应业务载荷、失败响应和重传的实际交付量需要统一计量，不含 TLS／TCP 协议开销。不能直接把官方固定秒数窗口或 UTC 月窗口当本项目自然月。
- 输入 Token 用对应模型分词器；输入加预留输出不得突破具体模型上下文，输出不得突破模型原生上限。缓存、推理 Token、多模态和流式 usage 的计量细则须由模型适配器确定，无法确认时不显示为“已支持”。
- Agent 的步数定义由注册运行契约明确；工具调用独立计数；总时长涵盖子调用。Skill 激活由运行时记录，脚本输出超限截断并明确反馈，纯指令包不虚构脚本执行。Worker 总时长包含排队及全部尝试，最大尝试次数为 1 时不重试；HTTP 连接结束不等于任务结束。
- 数据流是业务数据订阅，不是模型 SSE 响应。单条消息限制与代理压缩 record batch 的限制不是同一个参数，按协议适配并校验；订阅断开／恢复不得重置应用周期配额。周期额度耗尽时暂停交付并保留恢复位置，不删除积压。
- 超过入口频率／并发时拒绝新增调用；执行步数或时长到达上限时由运行时终止；调度队列达到上限时拒绝新增任务。结果超限策略需适配协议，不能一律称为 HTTP 429。
- 设置只维护域级边界。数据应用在允许范围内配置，仍经过应用版本审批和整体发版生效。收紧时任何运行应用不合规都应阻止保存，列出对象并要求先调整应用。适配器不支持、计量状态未知或取消不可保证时不得伪装成成功下发。

以上是把官方能力映射到本项目对象的设计推导，不是这些产品原生配置的逐字段复刻。
