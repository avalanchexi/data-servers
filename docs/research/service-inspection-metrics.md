# 服务运监：分类指标与交互说明

日期：2026-08-28。原型：`prototypes/runtime-management.html`。

## 页面与对象

原“运行监控”改为“服务运监”，同步导航、页面标题、面包屑与策略详情入口。页面右侧工作区内采用“应用目录 + 运行内容”双栏：目录位于工作区左侧，具体应用和服务运行内容位于右侧，二者独立滚动。

目录保留独立的“总览”入口，分类下仅列出数据应用，不展开第三层服务；固定版本服务引用仅在右侧应用详情清单中查看。进入服务运行视图后，左侧仍选中所属应用，右侧提供“返回应用”入口。应用消费形态取自 `CONTEXT.md`，分普通客户端、Agent、MCP、Skill、Worker；这与服务产品的 API、模型、Agent、MCP、Skill、Worker、数据流七种类型不同。一个 Agent 应用可以同时调用模型、API、MCP、Skill；不能因其依赖模型就归类为“模型应用”。逻辑表不提供直接调用，不进入本页运行清单。

本次覆盖六个离线应用示例和十三项服务引用。应用概览展示自身执行观测；服务视图的身份键为应用 + 服务 + 固定版本，不按服务名称合并。两个应用调用相同名称和版本的 MCP 时，调用数据仍隔离。

## 应用级核心指标

| 应用消费形态 | 核心指标 | 补充与注意 |
|---|---|---|
| 普通客户端 | 请求量、请求成功率、响应 P95、错误请求 | 只描述平台调用边界，不承诺客户端本身健康 |
| Agent | 结束运行数、运行成功率、平均执行步骤、工具调用次数 | 执行中、超时、运行 P95；不以内部调用量代替根运行数 |
| MCP | tools/call 次数、工具成功率、工具执行错误、工具 P95 | 传输/协议错误、tools/list 和 Tool 分布单列 |
| Skill | 激活、脚本执行、脚本失败、脚本 P95 | 需要执行端观测；下载或读取说明不是激活 |
| Worker | 完成任务、任务成功率、待处理任务、重试 | 执行中、最久等待、任务 P95、超时；逻辑任务与尝试次数分别计量 |

## 服务级差异

API、Agent、MCP、Skill、Worker 沿用相应语义，但只统计当前应用引用的固定服务版本。

- 模型：输入/输出 Token、首 Token P95、请求成功率；补充请求数、错误、降级、缓存与完整响应 P95。请求流中途失败必须反映到终态，不能只按 HTTP 200 判定。首 Token 只适用于流式请求，Token 用量缺失不能作为零。用量不在本轮换算为费用。
- 数据流：已确认消费消息、消费速率、当前消费积压、交付延迟 P95；补充活跃订阅、检查点距今、失败交付尝试。消息消费是窗口增量；积压图是各时点快照，不标成“条/3分钟”的吞吐。

所有成功率分母必须有明确观测对象。Agent/Worker 以窗口内结束的逻辑执行为分母，运行中、取消与未知终态不进入分母；超时属于失败子集。P95 来自当前范围的独立分布，不能平均服务分位数。本原型中的 P95 是独立样本字段，不用五个趋势点计算。

本地参考源码（相对于 `D:/cursor/himarket`）：

官方语义补充：

- [MCP Schema](https://modelcontextprotocol.io/specification/2025-06-18/schema)：工具结果 `isError` 表达工具执行失败，与协议级错误不同。原型把传输/协议失败和工具结果错误分成互斥类别，合并计算工具调用失败，不能把成功传输当作工具成功。
- [OpenTelemetry GenAI 观测说明](https://opentelemetry.io/blog/2026/genai-observability/)与[GenAI 属性说明](https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/)：模型运行具有 Token、请求持续时间、首响应等独立维度。相关规范仍在演进，生产适配需锁定版本；本页不是对某个 SDK 自动导出能力的承诺。
- Agent、Skill、Worker、业务数据流的执行语义继续遵循 `CONTEXT.md` 与 `settings-type-specific-limits.md`，需要对应运行时/适配器事件，不统一推断为网关原生指标。

## 示例、状态和交互

数据全部为 08-28 13:30–13:45 固定离线示例，五个趋势点分别统计三个分钟桶，积压例外为时点快照。此前只改变标签、未改变数据的 1 小时和 24 小时按钮移除；本轮不实现历史范围查询或实时采集。

代表性汇总：

- 客户服务门户：请求 18,000、错误 300，成功率 98.33%，与三个 API 服务引用的窗口量一致。
- 经营分析助手：结束运行 120、失败 6，成功率 95%；平均 11 步、工具调用 420。模型请求 1,000 次属于内部依赖调用，不能加到 120 次根运行上。
- 数据工具桥接：工具调用 80，传输/协议错误 1、工具执行错误 1，成功率 97.50%；同名工具服务在另一个应用下为 420 次调用、4 次失败。
- 自动报表脚本：外部执行未接入，因此激活和脚本指标未知；平台侧 API 的 60 次成功调用仍可单独查看。
- 数据同步任务：结束任务 240、失败 4，成功率 98.33%；待处理 12 为当前快照，重试 8 为执行尝试，不能相加为任务量。

总览只合计对象数量，不创建跨类型成功率或整体 P95。异常/降级应用按应用自身状态计数，不从其依赖状态机械推导。应用形态与服务类型的健康阈值尚未定义，原型状态只是示例。

查询只匹配应用或服务名称，不匹配消费形态、类型、状态或版本，不再提供额外筛选器。标题栏默认只展示“应用目录”和右端放大镜，不展示匹配数量。点击放大镜后，名称输入框在同一行替换标题并获得焦点，右端图标切换为关闭按钮，不向下新增搜索行；点击关闭时清除查询并恢复标题，避免隐藏条件。匹配应用名称时包含其服务清单；仅匹配服务名称时目录保留所属应用，右侧只列出匹配服务，不在左侧展开服务。查询结果同步目录和总览/清单，应用自身指标保持原范围并有说明。查询隐藏当前对象时返回查询总览、关闭旧抽屉；清除查询恢复完整目录。无结果有清除入口，分类折叠状态跨选择保留。

服务运行视图中的“查看详情”使用右侧只读抽屉，展示所属应用、类型、固定版本、当前指标与异常，并保留各指标的窗口量或当前快照口径；不提供保存、重跑、删除或权限变更。缺少数据时显示“—”与原因，不填充零或健康状态。平台托管与外部运行共用应用身份，但外部未上报的执行不能据平台调用成功推断。
