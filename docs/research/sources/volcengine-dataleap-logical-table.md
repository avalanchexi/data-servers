# 火山引擎 DataLeap：逻辑表创建、管理、使用与资产页信息

> 调研范围：火山引擎 DataLeap 的数据服务（OneService）逻辑表，不把数据地图中的物理元数据表、Flink 动态表或本项目自定义“逻辑表”概念混入结论。  
> 官网复核日期：2026-08-31（Asia/Shanghai）。  
> 证据方法：用真实 Chromium 重新访问火山引擎官方文档，读取当前页面正文、页面标题、最近更新时间及正文内官方产品截图 URL；并重新请求截图 CDN 字节核验。  
> 证据标签：**[正文事实]**＝官方文档正文明确说明；**[页面观察]**＝官方文档内产品页面截图可见、但正文未逐字段解释；**[推断]**＝基于多个事实的分析；**[公开资料未证实]**＝本次官方公开资料没有给出足够证据。

## 1. 先给结论

1. **正式定义与模块**：DataLeap 数据服务把“逻辑表”定义为数据开发者逻辑建模后产生的虚拟表，是物理表的映射，用于屏蔽底层存储、完成字段类型转换、规范命名和备份容灾配置。它位于 `DataLeap 租户控制台 > 数据服务 > 数据源 > 逻辑表`，不等同于 `数据地图 > 数据检索` 中由采集器接入的物理元数据资产。[正文事实，来源：[基本概念](https://docs.volcengine.com/docs/6260/127705?lang=zh)、[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)、[检索数据](https://docs.volcengine.com/docs/6260/71697?lang=zh)]
2. **来源**：标准路径的来源是已注册到数据服务的物理表。物理表来自 MySQL、ByteHouse、Doris 或 StarRocks 数据源；独立新建逻辑表时，待选区只显示创建成功且当前登录用户为 Owner 的物理表。[正文事实，来源：[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)]
3. **创建方式**：有三条官方路径：创建物理表时同时创建同名逻辑表；逻辑表“极简模式”按多张物理表批量创建；“标准模式（推荐）”基于一张物理表精细配置字段、查询约束、授权、目录、安全等级和下游 API 发布管控。[正文事实，来源：[物理表管理](https://docs.volcengine.com/docs/6260/127698?lang=zh)、[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)]
4. **生命周期边界**：逻辑表文档写的是单击“保存”完成创建，没有公开描述逻辑表自身的提交、审批、发布或上下线状态机。与“上线”有关的两个独立动作是：下游 API 发布可受该逻辑表的审核／通知规则管控；备份物理表可以打开“上线使用”，把实际流量切到备份表。[正文事实＋公开资料未证实，来源：[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)]
5. **逻辑表资产发现页**：OneService 中可验证的逻辑表资产页是 `数据服务 > 数据集市 > 逻辑表集市`。它面向同一业务线跨项目发现、查看详情和申请逻辑表权限；列表截图显示数据源类型、逻辑表名、负责人、最近更新时间、所属项目等信息。[正文事实＋页面观察，来源：[逻辑表集市](https://docs.volcengine.com/docs/6260/1148776?lang=zh)及其[官方原图](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_cd1eedd90d3c231488ae84d4d9080fb0.png)]
6. **不要把逻辑表集市和数据地图混称**：`数据地图 > 数据检索` 的当前官方“后续操作”类型清单列出 EMR Hive、LAS、ByteHouse、Doris、StarRocks、MySQL、PostgreSQL、SQLServer、Lance 等表类型，没有列出 OneService 逻辑表。因此公开资料不能证明 OneService 逻辑表会出现在通用数据地图资产页。[公开资料未证实，来源：[检索数据](https://docs.volcengine.com/docs/6260/71697?lang=zh)]

## 2. 正式定义、来源与产品位置

### 2.1 官网原词与含义

官网的核心原词是：“**逻辑建模后产生的虚拟表**”“**物理表的一个映射**”。其作用包括：

- 屏蔽底层存储细节；
- 物理表字段类型转换；
- 规范命名；
- 备份容灾配置。

这说明 DataLeap 数据服务的逻辑表不是一张新建的底层存储表，而是位于物理存储和 API 之间的逻辑映射／数据契约。[正文事实，来源：[基本概念](https://docs.volcengine.com/docs/6260/127705?lang=zh)，页面最近更新时间 2023.09.28 17:56:36]

### 2.2 产品位置

```text
DataLeap 租户控制台
└─ 数据服务（OneService）
   ├─ 数据源
   │  ├─ 物理表
   │  └─ 逻辑表  ← 创建与日常管理
   ├─ API         ← 使用逻辑表开发、测试、发布 API
   └─ 数据集市
      └─ 逻辑表集市 ← 同业务线跨项目发现、详情、申请权限
```

官方页面入口写法为：登录 DataLeap 租户控制台，在概览顶部进入“数据服务”，切换至“数据源”页签后进入逻辑表界面。[正文事实，来源：[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)，页面最近更新时间 2023.09.28 17:56:37]

### 2.3 标准来源链

```text
创建数据源
  → 把源库中的表/字段注册为物理表
  → 基于物理表创建逻辑表
  → 给项目授权／通过逻辑表集市申请权限
  → 脚本式、向导式标准模式或原生式 API 使用逻辑表
  → API 保存、测试、发布与调用
```

- 新建逻辑表前，官方要求已完成数据源创建和物理表创建。[正文事实]
- 物理表是在存储引擎中真实存在的表，其表／字段元数据被注册到数据服务平台。[正文事实，来源：[物理表管理](https://docs.volcengine.com/docs/6260/127698?lang=zh)]
- 逻辑表标准模式从已经创建成功且当前登录用户为 Owner 的物理表中选择来源。[正文事实]
- **边界**：API 开发页在 2026 年版本中新增了向导式“便携式”模式，可直接选数据源及数据表，不预先注册物理表和创建逻辑表。因此 2023 年《基本概念》中“配置 API 时必须使用逻辑表”的说法，不能再外推为当前所有 API 类型的绝对规则；它仍准确描述逻辑表标准路径。[正文事实＋推断，来源：[API 开发](https://docs.volcengine.com/docs/6260/127699?lang=zh)，页面最近更新时间 2026.01.15 10:51:10]

## 3. 创建／注册全过程

### 3.1 前置条件

| 环节 | 官网要求 | 证据性质 |
|---|---|---|
| 数据源 | 已创建数据源 | 正文事实 |
| 物理表 | 已创建物理表；标准模式待选区只出现创建成功且当前用户为 Owner 的物理表 | 正文事实 |
| 目录 | 可先在逻辑表目录树中“新建文件夹”，填写文件夹名称后确定 | 正文事实＋[官方入口截图](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_fc0d4ab5d6f8305599fa79afbb760474.png) |
| 角色 | 逻辑表创建页没有单独列出“仅某角色可创建”；不能把后续 API 开发的角色要求反推成逻辑表创建角色 | 公开资料未证实 |

### 3.2 路径 A：创建物理表时生成同名逻辑表

创建物理表时，完成库表选择和字段确认后，在“基本信息确认”中设置：

| 官网配置项 | 含义 |
|---|---|
| 安全等级 | L1-公开、L2-内部、L3-秘密、L4-机密 |
| `*创建同名逻辑表` | 选择是否同时创建同名逻辑表 |
| `*存储目录` | 指定同名逻辑表的目录 |

最后单击“保存”完成物理表创建。[正文事实，来源：[物理表管理](https://docs.volcengine.com/docs/6260/127698?lang=zh)及其[官方操作截图](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_e8e46c6f303a14ff408b00801399b989.png)]

### 3.3 路径 B：极简模式批量创建

在 `数据服务 > 数据源 > 逻辑表` 单击“新建逻辑表”，选择“极简模式”：

- 在待选物理表窗口同时选择多张物理表，批量生成多张逻辑表；
- 指定默认授权项目；
- 可编辑逻辑表名称与存储路径。

官方没有在该页公开极简模式的最大批量张数、重名策略和失败回滚规则。[正文事实＋公开资料未证实，来源：[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)]

### 3.4 路径 C：标准模式（推荐）单表创建

| 创建区块／官网字段 | 官网含义与规则 |
|---|---|
| 数据源类型 | MySQL、ByteHouse、Doris、StarRocks |
| 物理表选择 | 在对应类型下选择已创建成功且当前登录用户为 Owner 的物理表 |
| 逻辑表字段 | 默认展示物理表全部字段；可选所需字段，并编辑字段中文名、字段描述、字段安全等级 |
| 查询约束 | 用于避免慢查询，与主键无关；一条约束是一组字段，可多条。设置后，请求入参必须完整包含其中一条约束的全部字段，否则 SQL 无法执行 |
| 默认授权项目 | 创建时选择默认授权项目；创建后在“授权管理”查看已授权项目 |
| 逻辑表名称 | API 开发使用的标识，一般与物理表同名 |
| 存储目录 | 选择已创建的文件夹路径 |
| 安全等级 | L1-公开、L2-内部、L3-秘密、L4-机密 |
| 描述 | 逻辑表补充说明，供后续维护 |
| 下游 API 使用管控 | `API 发布审核`、`API 发布通知`、`无需发布管理` |

配置完成后单击“保存”，官方表述为“完成逻辑表创建”。[正文事实，来源：[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)]

### 3.5 权限与“上线”关系

- 创建时可选“默认授权项目”；创建后可在“授权管理”对新项目授权或回收权限。[正文事实]
- 逻辑表集市只解决**同一业务线内**的跨项目复用。若逻辑表未主动授权给项目，用户可申请权限；申请表包含：`申请逻辑表`（自动显示、不可编辑）、`申请内容`（“用于预览探查、逻辑表使用”，自动显示、不可编辑）、`*申请授权项目`、`*申请原因`（100 字符以内）。只能为自己已加入的项目申请。[正文事实，来源：[逻辑表集市](https://docs.volcengine.com/docs/6260/1148776?lang=zh)]
- 官网公开页没有说明申请的审批人、审批 SLA、是否可按字段／行／期限授权，也没有给出逻辑表自身的发布状态。[公开资料未证实]
- “下游 API 使用管控”控制 API 发布时是否审核／通知，不是逻辑表自身上线。[正文事实]
- “设置主备关系”中的“上线使用”只表示把实际流量路由到选定备份物理表，不是发布逻辑表。[正文事实]

## 4. 创建后的查看与管理

### 4.1 正文明确的详情模块

逻辑表详情由以下部分组成：

1. **基础信息**：正文明确举例表名、数据源类型、存储路径、负责人；“更多”中可编辑、加标签、设主备、删除。
2. **字段信息**：查看并编辑表字段。
3. **预览探查**：抽样数据与 SQL 探查；支持查询示例、运行、格式化、全屏，运行后显示结果和查询日志。
4. **授权管理**：查看所属／已授权项目，对新项目授权或回收权限。
5. **变更记录**：查看字段更新记录，并可回退到历史版本。

[正文事实，来源：[逻辑表管理](https://docs.volcengine.com/docs/6260/1154905?lang=zh)；预览页面[官方原图](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_c25dcf344800cb02e8f420b49b74f220.png)]

### 4.2 字段和映射管理

- 字段编辑支持修改：字段名称、字段中文名、字段类型、字段描述、安全等级、主键信息、关联指标／维度。[正文事实]
- 可切换来源物理表，并重新做逻辑字段到物理字段的映射；映射支持手动拖拽、同名映射、同行映射。[正文事实]
- 官方提示字段编辑要考虑对下游的影响。[正文事实]

### 4.3 基本信息、标签、负责人、目录

- “更多 > 编辑”可调整默认授权项目（多选）、安全等级、描述、查询约束、标签、下游 API 使用管控。[正文事实]
- 目录树中的单表操作包括标签、变更负责人（改为当前项目其他成员）、移动、删除。[正文事实]
- 搜索支持逻辑表名／ID／负责人／描述；高级搜索可指定搜索范围、数据源类型、标签、负责人。[正文事实＋[官方搜索截图](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_a5e29d56063c3e4546323cc0ab26302a.png)]

### 4.4 主备、切换与删除约束

- 整表备份要求主、备物理表数据源类型相同、字段完全一致；可添加多个备份物理表并配置字段映射。[正文事实]
- 开启某备份表的“上线使用”后，实际流量访问该备份表。[正文事实]
- 删除需要二次确认；若逻辑表已有 API 关联，则不能删除。[正文事实]
- 详情页“更多”中可见“编辑／设置主备关系／删除”。[页面观察，来源：[官方详情操作截图](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_6c60608e1652545427e1f72fcb11d2d5.png)]

## 5. 逻辑表如何被使用

### 5.1 项目内 API 开发

API 开发前，当前官网要求：

- 已加入数据服务项目，角色为“数据开发”或“项目管理员”；
- 已创建物理表和逻辑表，并拥有表的读权限。

[正文事实，来源：[API 开发](https://docs.volcengine.com/docs/6260/127699?lang=zh)]

标准逻辑表使用方式：

| API 类型 | 逻辑表使用方式 |
|---|---|
| 脚本式 | 自定义 SQL；同源多张逻辑表，最多 10 张；“表字段”弹窗显示所选逻辑表字段 |
| 向导式标准模式 | 单张逻辑表；请求参数形成 WHERE 字段，返回参数形成 SELECT 字段，系统生成 SQL |
| 原生式 | 圈选同源逻辑表，最多 5 张，由用户动态传入 SQL，面向动态分析 |

API 的请求／返回参数均可绑定逻辑表字段。API 后续流程为保存、测试、发布；这是 API 生命周期，不应写成逻辑表发布流程。[正文事实，来源：[API 开发](https://docs.volcengine.com/docs/6260/127699?lang=zh)]

### 5.2 跨项目发现和复用

```text
概览 > 数据服务 > 数据集市 > 逻辑表集市
  → 搜索同业务线其他项目的逻辑表
  → 查看详情（字段信息／预览探查／授权管理）
  → 若未主动授权，则选择自己已加入的项目并填写原因
  → 申请“预览探查、逻辑表使用”权限
```

官网只证明可“申请权限”，没有公开说明完整审批流和审批角色。[正文事实＋公开资料未证实，来源：[逻辑表集市](https://docs.volcengine.com/docs/6260/1148776?lang=zh)]

### 6.3 通用 `数据地图 > 数据检索` 的边界

当前《检索数据》正文说数据检索首页展示最近浏览库／表、已接入资产类型及数量，并支持按数据类型、库、负责人、生命状态、业务线、项目、主题、标签筛选。其“后续操作”列出的详情类型包括：EMR Hive、LAS、LAS Catalog、ByteHouse CDW／CE、EMR Doris／Serverless Doris、EMR StarRocks／Serverless StarRocks、MySQL、PostgreSQL、SQLServer、Lance。

该清单没有“OneService 逻辑表”。所以：

- 可以确认通用数据地图管理多种物理元数据资产；
- 不能确认它也展示 OneService 逻辑表；
- 关于逻辑表的列表／详情字段，应以“逻辑表集市”和“逻辑表管理”页面为准。

## 7. 公开资料未证实项

本轮不应写成产品确定能力的事项：

1. 逻辑表自身存在草稿／待审核／已发布／已下线等状态机；
2. 逻辑表创建需要哪一个固定系统角色（官网只明确待选物理表 Owner 条件；API 开发角色不能反推）；
3. 权限能否按字段、行、数据范围或有效期授予；
4. 逻辑表权限申请的审批人、审批流程、SLA 和自动失效规则；
5. 极简模式的批量上限、重名处理和失败回滚；
6. OneService 逻辑表进入 `数据地图 > 数据检索／资产目录`；
7. 官方公开 API 中可创建／编辑／删除 OneService 逻辑表的稳定接口。本次官方产品 API 公开材料未找到可据此下结论的端点。
