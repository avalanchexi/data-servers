# 运行情况：注册中心、AI 治理中心与沙箱指标

调研日期：2026-08-28。适用原型：`prototypes/archive/2026-09-02/runtime-management.html`。

## 结论与边界

三类实例不能套用网关的上下游 QPS、服务错误率和慢响应榜单。原型沿用已确认的左侧实例目录，右侧分别呈现四项指标、两张同单位趋势图、类型化明细和最近异常。明细以右侧只读抽屉展示；没有配置、重启、任务重跑或资源删除操作。

页面所有数值均为离线示例，不是本机参考系统或生产采集结果。下列“原生字段”表示来源具备相应语义，不表示本仓库已经接入接口。“适配器派生”表示仍需后端采集、窗口化与去重。当前仅实现 HTML 展示和交互。

AI 治理中心的含义以本地参考实现为准：管理 AIRegistry 命名空间中的 Skill 资源与版本分发，不是内容安全拦截中心。平台 UI 保持“注册中心、AI 治理中心、沙箱”等中立命名。

## 1. 注册中心

| 页面指标 | 来源与计算 | 范围 |
|---|---|---|
| 注册服务数 | Nacos naming `serviceCount`；按命名空间、分组、服务名去重 | 当前快照 |
| 健康注册目标 / 已注册目标 | 注册目标清单的真实 `healthy` 状态；总量可用 `ipCount` 对照 | 当前快照 |
| 订阅关系数 | `subscriberCount` 或服务订阅清单；同一客户端订阅多个服务分别计数 | 当前快照 |
| 推送成功率 | 适配器归一化推送结果后，成功尝试 / 全部尝试；参考 `totalPush`、`failedPush` | 近 15 分钟 |

右侧推送次数、失败次数分别按 3 分钟桶显示，纵轴独立标注，避免失败量被大流量淹没。服务明细展示健康/注册目标、订阅关系、推送/失败和目标健康状态；推送失败与目标不健康不是同一状态。

采集注意：不得直接叠加多个节点返回的集群库存；服务、目标和订阅需要稳定键去重。不同 Nacos 版本及导出方式可能具有不同指标类型与重置行为，不能未经验证对 gauge 使用 `increase`，也不能把进程累计值当作窗口总量。目标的 `healthy` 与 `enabled` 不同；保护阈值、权重等也会影响实际发现结果，健康目标比不是流量可达性的承诺。

官方依据：[监控指标](https://nacos.io/docs/latest/manual/admin/monitor/)、[健康检查与实例元数据](https://nacos.io/docs/latest/manual/user/naming/health-and-metadata/)。

## 2. AI 治理中心

| 页面指标 | 来源与计算 | 范围 |
|---|---|---|
| Skill 资源数 | 资源列表按命名空间、资源名称去重 | 当前快照 |
| 已上线版本 | 版本状态 `online`，与资源数分开统计 | 当前快照 |
| 待审核版本 | 版本状态 `reviewing`；不算运行异常 | 当前快照 |
| 下载成功率 | 分发适配器记录已结束的版本包传输尝试，成功 / 全部 | 近 15 分钟 |

明细按资源展示已上线固定版本、版本状态分布、累计下载以及近 15 分钟下载/失败。抽屉列出全部具体版本。累计 `downloadCount` 不是窗口请求数；获取下载地址成功也不等于实际传输成功。下载、授权与 Skill 执行是三个不同结果，不能互换成功率。

官方 AIRegistry 支持多类 AI 资源；本次根据本地 HiMarket 的已实现用途，只选取 Skill 资源治理与分发。没有新增 Prompt 产品、AgentCard 管理或审批流程；上线版本不代表任何数据应用自动获权，仍要求应用引用固定版本。

官方依据：[AI Registry 概览](https://nacos.io/docs/latest/manual/user/ai/ai-registry-overview/)、[AI 资源生命周期](https://nacos.io/docs/latest/manual/user/ai/ai-resource-lifecycle/)。这些文档定义资源与状态，不提供本页全部时序指标的现成采集契约。

本地参考证据（相对于 `D:/cursor/himarket`，只读检查）：

- `himarket-web/himarket-admin/src/i18n/locales.ts`：`nav.airegistryInstances` 对应 AI 治理中心，说明其用于 Agent Skill 命名空间配置。
- `himarket-web/himarket-admin/src/pages/AiRegistryConsoles.tsx`：实例配置、默认实例及连接检查，没有现成的治理指标大盘。
- `himarket-server/src/main/java/com/alibaba/himarket/service/impl/AiRegistrySkillServiceImpl.java`：资源/版本查询、发布、审核、上下线及下载。
- `himarket-server/src/main/java/com/alibaba/himarket/dto/result/airegistry/AiRegistrySkillResult.java`：资源包含 `downloadCount`、`latestVersion`，不能由此直接推导周期成功率。

## 3. 沙箱

| 页面指标 | 来源与计算 | 范围 |
|---|---|---|
| 当前执行中 | 适配器按执行 ID 跟踪尚未结束的任务 | 当前快照 |
| 执行成功率 | 成功 /（成功 + 失败 + 超时），按结束时间归入窗口 | 近 15 分钟 |
| 超时执行 | 明确由执行时限触发终止的次数，是失败子集 | 近 15 分钟 |
| P95 执行耗时 | 窗口内已结束成功/失败/超时的耗时，示例按最近秩计算 | 近 15 分钟 |

状态条独立展示逻辑隔离范围“数据应用 × 环境”、生命周期、执行器就绪及到期时间。当前执行器健康不意味着所有任务成功；任务超时不直接把沙箱标为不可用。生命周期到期、执行时限、客户端等待超时也不能混为一谈。

执行中、取消、结果未知的记录不进入成功率分母或耗时分位。真实采集应保证开始/结束事件配对、按执行 ID 去重，显式记录取消、丢失终态和超时原因。代码执行上下文数不等于运行任务数；HTTP 请求完成也不等于异步任务结束。

官方依据：[架构](https://open-sandbox.ai/architecture/)、[API 规范](https://open-sandbox.ai/api/)。生命周期接口、`/ping`、命令状态与执行 SSE 为接入依据；页面成功率和 P95 是应用执行适配器派生指标，不是原生 `/metrics` 的现成字段。诊断日志/事件接口不提供统一结构化审计模型。原生 CPU、内存、容器与节点指标不进入本次业务运行视图。

## 4. 示例数据与一致性

统一示例时段 13:30–13:45；五个趋势桶分别截至 13:33、13:36、13:39、13:42、13:45。窗口按左开右闭归档。

- 注册中心：4 个服务，12 个注册目标中 11 个健康，18 条订阅关系；推送 1,200 次、失败 3 次，成功率 99.75%。
- AI 治理中心：4 个 Skill、6 个版本，其中上线 3、待审核 1、草稿 1、下线 1；累计下载 1,890，窗口下载尝试 200、失败 2，成功率 99.00%。
- 沙箱：2 次执行中；窗口结束 6 次，其中成功 5、超时 1，成功率 83.33%；耗时序列为 8、12、20、24、36、120 秒，最近秩 P95 为 120 秒。结束桶总量 6、失败桶总量 1。

库存数、累计数、窗口尝试数和当前并发分别标注，不相加。网关概览中的类型、实例名称、状态、关联对象和抽屉来自同一数据源；“关联对象”按类型分别写明服务、Skill、执行。运行总览的 QPS 和请求成功率仍只汇总网关服务，分类运行摘要提供三个独立入口，不把下载数或任务数混入请求指标。
