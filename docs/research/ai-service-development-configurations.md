# AI 服务开发：类型专属配置调研与原型建议

调研日期：2026-08-28。状态：类型专属配置、数据需求与托管分流已按用户确认落入离线原型；框架能力表仍是参考，不代表已选定或接入生产运行框架。

## 1. 结论与适用范围

这里创建的是服务开发草稿或非托管数据需求记录，不是消费服务的数据应用。用户确认采用“公共创建入口 + 公共数据需求 + 托管时的四类专属开发工作台 + 提交审核”。Agent、MCP、Skill、Worker 的代码、契约、依赖和执行语义不同，不能只改类型名称后共用 Agent 表单；非托管分支不开发或部署外部实现。

本文以 LangChain / LangGraph、Google ADK、MCP 协议、Agent Skills 格式、Temporal / Celery 为代表性参考，不把它们视为同一套标准，也不将所有框架选项并集都塞进首期界面。MCP 字段核对采用固定的 2025-11-25 协议文档，不宣称该修订是最新版本；实现时应按实际 SDK、客户端与网关适配器确认兼容范围。

下文区分三种依据：

- **协议或格式要求**：选用对应协议、格式后需要遵守。
- **框架能力参考**：常见实现提供的能力，不代表所有运行时都支持。
- **本平台建议**：基于本项目边界对字段、交互和默认行为的设计建议；本轮已实现范围以第 8 节为准，其余不视为已实现功能。

### 改造前的具体缺口（本轮已修复）

改造前核对 `prototypes/ai-service-development.html`：

- `createServiceModal()` 能选择四种类型，但提交只切换到同一个 `workbench`；输入的名称、说明未成为工作台所用服务对象。
- `workbenchView()` 的标题、开发导航、编辑区仍固定为“客户洞察 Agent”。
- `editorDefinition()` 只有 Agent 目标、Prompt、Memory 和调用模式等内容；AI 变更集也固定为 Agent 示例。

本轮已改造服务草稿模型、类型路由、编辑内容及 AI 上下文，不能只给创建弹窗增加几个输入框。以上缺口来自源码检查，不是浏览器运行验证。

## 2. 先确定配置归属

本项目已要求专属编辑器、固定依赖版本、服务与消费身份分离，以及 AI 只生成可审查变更。依据为根目录 `CONTEXT.md` 的“AI 服务开发”“服务依赖”“AI 辅助开发”和 Design Constraints，以及 `docs/adr/0001`、`0002`、`0003`。

| 配置层 | 应放内容 | 不应混入的内容 |
| --- | --- | --- |
| 创建弹窗 | 类型、服务名称、服务说明、是否平台托管；托管时提供创建方式 | 完整协议编辑、运行凭据、生产部署参数 |
| 公共数据需求 | 数据资产选择、所需字段、行范围、使用用途；或显式不使用平台数据 | 生产明文数据、直接授权、运行密钥 |
| 托管服务开发草稿与版本 | 实现代码、输入输出契约、依赖固定版本、执行要求、仿真用例、说明文档 | 实际业务数据权限、跨应用共享凭据 |
| 非托管需求修订 | 数据需求保存、人工提交与审核记录 | 类型开发配置、测试、部署、外部能力产品生命周期 |
| 数据应用装配 | 获批服务版本、应用身份、获批数据与操作范围、实际运行参数、应用配额 | 修改被引用服务的已发布实现 |
| 平台运行与发布 | 运行时配置档案、实际端点、凭据注入、制品构建与签名、执行策略 | 让开发者填写集群、Pod、管理员密钥或签名私钥 |

服务开发可以声明“需要访问什么、需要怎样执行”，但不因此获得生产访问权。服务默认值不得突破公共上限；应用可以在已批准契约允许的范围内收窄。代码和运行时限制的实际执行能力必须通过适配验证，不能用表单字段代替实现。

## 3. Agent：行为、工具与状态作为整体开发

### 官方依据

LangChain 的 Agent 配置围绕模型、工具、系统指令、结构化输出和状态展开；人工介入可以放在特定工具动作前。ADK 同样提供模型、指令、工具和输入输出结构配置，但结构化输出与工具联合使用的支持情况受模型影响。[LangChain Agents](https://docs.langchain.com/oss/python/langchain/agents)、[ADK LlmAgent](https://adk.dev/agents/llm-agents/)

LangGraph 将线程内检查点和跨线程长期存储区分开；这说明“开启记忆”不足以表达存储范围、恢复与保留策略。[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)

### 本平台字段建议

“必要”指运行相关仿真前需要完整表达，不要求创建草稿时一次填完；这是本平台建议，不是统一 Agent 标准。

| 配置组 | 主要字段 | 必要性与联动 |
| --- | --- | --- |
| 行为定义 | 任务目标、系统指令、指令变量及变量来源、实现代码或配置入口 | 必要；指令与实现属于同一整体制品 |
| 模型与输出 | 获准模型服务及固定版本、输出格式；支持时展示生成参数、结构化输出约束 | 使用模型时必要；不支持的参数不展示；不能只改下拉框就假定模型能力兼容 |
| 工具与依赖 | 工具选择、用途、参数映射；模型、API、MCP、Skill 的固定版本引用 | 按需；纯本地辅助函数可留在制品内，受管依赖遵守平台注册边界 |
| 状态与记忆 | 无持久化、会话状态、长期记忆；保留策略、写入条件、恢复方式 | 按需；会话状态与长期记忆分开；隔离继承数据应用和运行环境，不能跨应用共享 |
| 调用契约 | 同步会话、异步任务或两者；输入输出结构、错误、流式返回能力 | 必要；异步模式再表达任务查询和取消能力，不默认承诺所有能力均可用 |
| 执行约束 | 最大执行步数、工具调用次数、总时长；敏感动作确认点、失败处理 | 使用平台支持的限制；与应用配额分开；生产确认不能被 Prompt 或开关绕过 |
| 仿真验证 | 受控输入、预期结果、工具调用轨迹、越权拒绝、人工确认与恢复场景 | 按所选能力提供用例，不在本轮新增跨类型质量分数或发布阈值 |

建议开发导航：`行为与模型 / 工具与依赖 / 状态与记忆 / 调用契约 / 仿真测试 / 修订与版本`。Prompt、Tools、Memory 只是编辑分区，不分别建立产品或审核生命周期。不强制新增可视化节点编排或多 Agent 框架选择器。

## 4. MCP：协议契约与服务实现

### 官方依据

MCP 服务可声明工具、资源、提示模板等能力。工具具有名称和输入 JSON Schema，可提供输出 Schema 及行为提示；资源以 URI 或 URI 模板组织；提示模板具有名称、参数及生成的消息内容。这三类不是同一个“工具参数表”，也不要求每个服务全部提供。[Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[Resources](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)、[Prompts](https://modelcontextprotocol.io/specification/2025-11-25/server/prompts)

核对的协议修订定义 stdio 与 Streamable HTTP；前者由客户端启动子进程，后者用于独立服务进程。Streamable HTTP 可以使用 SSE，并不等于旧版 HTTP+SSE 传输。[MCP Transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

### 本平台字段建议

| 配置组 | 主要字段 | 必要性与联动 |
| --- | --- | --- |
| 服务定义 | 服务标识、实现版本、SDK/运行时档案、实现入口、协议兼容范围 | 必要；原生开发形成可托管制品，不只是登记一个外部地址 |
| 能力声明 | Tools、Resources、Prompts | 按实际实现选择；相应开发分区随之出现，不强制同时启用 |
| 工具契约 | 工具名、用途说明、输入 Schema、可选输出 Schema、处理函数、结果与错误映射 | 启用 Tools 后按工具配置；无参数工具仍需合法输入 Schema |
| 资源契约 | 资源名称、URI/模板、MIME 类型、读取实现；可选订阅能力 | 启用 Resources 后出现；资源标识不是任意文件系统访问权限 |
| 提示模板 | 模板名称、用途、参数、消息模板及资源引用 | 启用 Prompts 后出现；它不是 Agent 的顶层系统指令 |
| 托管与安全 | 受管传输档案、依赖与所需范围、身份接收约定、单次处理超时与取消支持 | 建议平台远程托管优先 Streamable HTTP；stdio 仅在已支持的开发/运行适配场景使用 |
| 协议测试 | 初始化及能力发现、对应 list/get/read/call、参数校验、错误结果、身份范围 | 随能力选择变化；不以 Agent 回答是否自然作为主要验收对象 |

注意：工具的只读、破坏性、幂等性等 annotations 是行为提示，不等于获批权限或已经验证的安全保证。MCP 可以有内部实现依赖，但不能因为属于 AI 服务就强制出现模型、Memory 或任务调度字段。

建议开发导航：`能力与契约 / 服务实现 / 依赖与身份 / 协议测试 / 修订与版本`；能力与契约内再按选择展示工具、资源、提示模板。平台实际端点在发布后生成或绑定，不能把原生开发变成外部服务注册。

## 5. Skill：说明与资源组成的版本化能力包

### 官方依据

Agent Skills 格式要求包内有 `SKILL.md`，其 frontmatter 的 `name` 和 `description` 必填；正文承载使用指令。脚本、参考资料和资源目录均可选，`license`、`compatibility`、`metadata` 为可选元数据；`allowed-tools` 是实验性字段，支持情况因实现而异。格式本身不规定所有 Skill 必须具有独立服务端点、模型配置或运行进程。[Agent Skills Specification](https://agentskills.io/specification)

### 本平台字段建议

| 配置组 | 主要字段 | 必要性与联动 |
| --- | --- | --- |
| 技能元数据 | 技能标识、能力与适用场景描述；可选许可证、兼容性与标签 | 格式必要字段映射到 SKILL.md；中文服务展示名称与包标识分开，不直接把中文名称写成包目录名 |
| 使用说明 | 激活时机、使用步骤、输入输出示例、失败处理、注意事项 | 正文必要；适用场景描述服务于发现和选择，不做保证自动命中的规则引擎 |
| 文件内容 | SKILL.md、scripts、references、assets 及其他文件 | 文件树与正文/代码编辑；不要求每个 Skill 都包含脚本 |
| 脚本执行 | 脚本文件、运行依赖、参数约定、所需网络/文件权限、执行时限 | 仅有脚本时出现；脚本路径不是 Skill 统一必填启动命令 |
| 受管依赖 | API、MCP、数据资产及包内脚本引用 | 按需；包里只声明身份与凭据需求，不包含平台凭据原文 |
| 打包与交付 | 包内容清单、固定版本、摘要、签名校验结果 | 签名是本平台交付治理，不是 Agent Skills 格式的通用必填字段；私钥不进入开发表单 |
| 验证 | 格式与引用有效性；有脚本时增加仿真运行与输出验证 | 说明型 Skill 不强制增加没有意义的脚本测试 |

建议开发导航：`技能说明 / 文件与资源 / 依赖与权限 / 包验证 / 修订与版本`。默认打开 SKILL.md 的可编辑内容；纯说明型不展示模型参数、端口、Memory、并发运行实例或定时任务。

本项目同时支持平台 Agent 装配与外部固定版本交付；签名只证明来源与版本，不证明外部实际执行代码未被改动。运行权限仍由宿主与数据应用授权约束，不能把 `allowed-tools` 当作绕过授权的开关。

## 6. Worker：任务契约与执行可靠性

### 官方依据

“Worker”不是与 MCP 同级的统一协议。在 Celery 中，任务函数、任务名称、消息与执行 Worker 关联；重试和消息重新投递可能导致重复执行，需要考虑幂等性。Temporal 则区分任务/活动实现、执行与 Worker，提供可配置的重试间隔、退避和不可重试错误。[Celery Tasks](https://docs.celeryq.dev/en/stable/userguide/tasks.html)、[Temporal Error Handling](https://docs.temporal.io/develop/python/best-practices/error-handling)

Temporal 区分单次尝试时长与包含重试的总执行期限，长任务可用心跳报告进展；这些是运行时能力，不能仅靠声明获得。定时任务还需处理时区及重叠执行问题。[Temporal Activity Failures](https://docs.temporal.io/encyclopedia/detecting-activity-failures)、[Temporal Schedules](https://docs.temporal.io/develop/python/workflows/schedules)、[Celery Periodic Tasks](https://docs.celeryq.dev/en/stable/userguide/periodic-tasks.html)

### 本平台字段建议

| 配置组 | 主要字段 | 必要性与联动 |
| --- | --- | --- |
| 任务定义 | 任务标识、用途、处理入口、语言/运行时档案、依赖与构建清单 | 必要；入口为受控制品内的实现引用，不提供任意系统命令入口 |
| 输入输出 | 输入 Schema、结果 Schema 或制品引用、错误分类、状态与进度约定 | 必要；与 Agent 对话消息、MCP 工具契约分别建模 |
| 触发能力 | 按需异步提交、平台定时触发 | 首期按项目既有边界提供；不新增事件流触发与复杂任务 DAG |
| 调度模板 | 频率/时间表达、时区、重叠处理、输入参数模板 | 选择定时能力后出现；草稿不创建真实计划，实际调度需绑定获批数据应用身份 |
| 超时与重试 | 单次执行时限、整体期限、最大尝试次数、退避、可重试与不可重试错误 | 明确整体期限是否包含排队和重试；建议统一以“最大尝试次数（含首次）”显示，由适配器转换各框架语义 |
| 幂等与恢复 | 业务幂等标识来源、重复请求处理、失败后的人工重试；可选心跳、检查点、取消 | 有副作用和自动重试时重点配置与验证；不能声称配置幂等键就实现了 exactly-once |
| 执行资源 | 平台资源档案、任务并发要求、临时存储需求、允许的依赖访问 | 在平台支持范围内选择；实际队列、部署资源和应用额度不作为自由填写的基础设施参数 |
| 仿真验证 | 正常完成、非法输入、超时、重试耗尽、重复提交、取消及恢复 | 仅为所支持能力提供场景；没有接入相应运行时的能力应明确标记待适配 |

建议开发导航：`任务实现 / 输入输出 / 触发与恢复 / 运行要求 / 仿真测试 / 修订与版本`。只有业务实现确实调用模型时才选择模型依赖，不让每个 Worker 都填写 Prompt 或 Memory。

## 7. 创建弹窗如何联动

以下为本平台交互建议，不是上述规范要求的 UI。

公共部分保留：服务类型、服务名称、服务说明，并新增“AI 服务是否托管：是 / 否”。名称与说明继续默认空且必填。选择“是”才显示“AI 对话创建 / 手工创建”，选择“否”隐藏创建方式，进入仅数据需求的详情页。切换托管方式保留已填名称、说明和原托管创建方式。

两种创建方式对应同一服务草稿的两种开发工作区，而不是两种服务产品。AI 对话创建以左侧 MaaS 开发 Agent 会话为主，右侧“服务配置”展示数据需求、类型专属配置、依赖和修订状态；点击后在右侧相邻位置展开只读配置抽屉。“AI 辅助开发 / 手工开发”切换位于“服务配置”标题下，页面顶部只保留保存、仿真校验和提交审核等业务操作。需要修改时，由开发 Agent 生成待采纳变更，或切换到手工开发。手工创建进入类型专属表单编辑器，切换入口同样收纳在服务配置目录中，所有配置由开发者直接执行。

可编辑草稿和新修订支持在同一服务内切换开发方式，每次切换形成草稿修订记录；审核中、审核通过和已上线内容保持只读。若 AI 会话中存在待采纳变更，必须先接受或放弃再切换。测试、提交审核、审批和上线始终由人工执行。托管方式与开发方式保持正交，非托管服务不出现开发方式切换。

所有类型创建后统一先进入“数据需求”。以下轻量类型选项仍可作为后续创建体验建议；本轮将它们留在详情页联动，避免扩大创建弹窗。

| 选择类型 | 创建阶段可出现的轻量选项 | 创建后默认进入 |
| --- | --- | --- |
| Agent | 调用模式：同步会话 / 异步任务 / 两者 | 数据需求 → 行为与模型 |
| MCP | 初始能力：工具 / 资源 / 提示模板，可多选 | 数据需求 → 对应能力契约 |
| Skill | 初始包模板：说明型 / 含脚本；这是初始化模板，不是不可更改的产品子类型 | 数据需求 → 技能说明 |
| Worker | 支持触发：按需异步 / 平台定时，可多选 | 数据需求 → 任务实现 |

这些选项用于初始化工作区，不要求立即选择所有依赖、填写完整契约或部署参数。模型选择、Schema、脚本、重试等复杂内容放在开发页；运行时档案可以由模板预置并在页面中核对，不强迫用户在创建时选择具体框架品牌。

### 类型切换必须带来的变化

1. 创建前切换类型保留名称、说明和创建方式；类型专属临时值按类型隔离，不能将 Agent 字段写入 Skill 草稿。
2. 创建后持有真实的服务名称、说明和不可混淆的类型标识，并进入该类型工作台，不再显示固定的客户洞察 Agent。
3. 默认页签、字段、依赖可选类型、仿真场景、AI 上下文与差异预览同时随类型变化。
4. 草稿创建后，建议不提供随意改类型；需要另一种类型时新建草稿，避免原有契约、修订和测试被错误复用。
5. 所有类型复用服务信息、数据需求、保存和审核。只有托管服务再复用 AI 助手、仿真入口、修订与版本；复用入口不等于复用所有内部内容。
6. AI 生成的变更仍先展示差异，由开发者接受后形成修订；测试、提审、审批和上线继续由既有人工流程控制。
7. 解释性文字沿用已确认的圆形问号悬停帮助，同时可通过聚焦访问；必要标签、必填标记和校验错误直接可见，不能全部藏进帮助。
8. 保存草稿允许尚未完成的内容；运行所选仿真前检查该类型必要字段。不在本轮另行定义公共质量门禁、自动上线或新的审批策略。

## 8. 本轮落地范围与验证边界

用户确认直接修改 `prototypes/ai-service-development.html`。实现范围：

- 平台托管服务在创建时选择 AI 对话创建或手工创建；看板卡片显示当前开发方式。AI 工作区采用“会话 → 服务配置 → 按需展开的只读配置抽屉”的从左到右顺序；开发方式切换置于服务配置标题下。手工工作区保留类型专属编辑器，不显示 AI 生成入口。
- 可编辑草稿支持原位切换开发方式并记录修订；待采纳 AI 变更会阻止切换。修订与审核记录只能由系统生成，AI 配置抽屉不提供调整入口。
- 创建信息形成独立服务对象，名称、说明及类型不再丢失；托管方式创建后固定，防止切换时丢失实现。
- 四类服务公共数据需求：可检索资产、多选资产、选择字段、配置业务域范围或等值条件、填写用途、移除需求、显式不使用平台数据。
- 托管 Agent 提供行为/模型/记忆/契约/执行边界；MCP 按 Tools、Resources、Prompts 勾选显示对应契约；Skill 以 SKILL.md 和资源内容为中心，仅含脚本时显示运行配置；Worker 提供任务实现、契约、触发、时限、重试与幂等键，定时字段按需展示。
- 非托管分支只有数据需求与审核记录，无开发配置、AI 助手、测试和部署入口；相关事件处理也检查托管方式，不仅隐藏按钮。
- 保存和创建写入命名隔离的浏览器本地存储，存储不可用时提示仅当前页面保留。离线原型不访问后台；测试和提交使用真实内联脚本的字段/结构校验，不执行代码。
- 人工确认提交后冻结快照并进入待审核；模拟驳回必须填写意见，修改后可重提并保留历史快照。托管提交形成独立版本号，非托管只形成需求修订；审核通过不授予数据权限。仅托管且已审核通过时出现独立的模拟发布动作。
- 看板按真实服务对象显示数量、类型和状态；类型筛选、新建卡片及重新打开详情可操作。旧 A/B 只保留为历史比较入口，本轮验收以默认 C 为准。
- 草稿配置（含已驳回）和仿真测试卡片增加“删除”，二次确认明确服务名称和影响；删除标记持久化后同步隐藏卡片、更新分类和泳道数量，刷新不会恢复。待审核、审核通过、已上线及已有审核通过/上线历史的新修订不开放整项删除；确认时再次检查状态。本地记录和审核快照保留，不执行后台删除。
- 泳道最小宽度为 320px，仅看板工作区横向滚动，类型目录保持固定，各泳道内部纵向滚动。范围说明浮层放在页面根层，支持悬停、聚焦、点击及 Esc 关闭，并按视口边缘定位，避免被侧栏滚动容器裁切。
