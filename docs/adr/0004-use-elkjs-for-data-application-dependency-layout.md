# 使用 ELK.js 布局数据应用依赖关系图

数据应用依赖关系图具有固定的左到右业务分层、可变尺寸卡片、共享依赖、多入多出端口和不可避免的边交叉；现有基于 DOM 位置逐边拼接路径的实现只能局部避障，无法同时优化节点顺序、交叉数和折点数。采用 `ELK.js Layered` 在 Web Worker 中统一计算确定性的节点位置、端口和正交路径，渲染层再以跨线冲突图着色和弧桥区分必要交叉。审批正文仅保留摘要，完整结构化依赖事实保存在不可变快照中，关系图可由快照生成附件，像素坐标不属于领域数据。

## Considered Options

- 继续维护自研路由：不增加依赖，但每增加一种图形结构都要补充局部规则，难以给出全局质量保证。
- 使用 Dagre／Cytoscape：可以完成有向分层，但不能单独满足当前四侧端口、可变节点、正交避障和稳定路径的组合要求。
- 使用 ELK.js Layered：增加布局依赖和异步计算边界，但直接支持 Sugiyama 分层、交叉最小化、端口约束与正交路由。

## Consequences

- 图的结构化事实与布局结果分离；步骤 4、步骤 5 和审批附件使用同一事实与稳定排序种子。
- 节点只在所属业务层内上下调整；跨层关系总体向右，同层关系才以上下端口为主。
- 必要交叉由渲染层使用不同线路颜色和弧桥表达，颜色不是唯一识别手段。
- 布局失败时显示三层无连线清单并允许重试，不回退到旧路由，也不阻断权限核对。
