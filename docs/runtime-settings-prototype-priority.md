## 1. 分级标准

### 产品重要性

| 等级 | 含义 |
|---|---|
| 高 | 决定统一网关能否形成完整产品闭环，或属于多租户、环境、服务运行的基础模型 |
| 中 | 提升运行治理与问题定位能力，但不影响首版核心业务闭环 |
| 低 | 偏底层实现、平台公共能力或首版演示不需要展开的高级能力 |

### 首版原型建设优先级

| 优先级 | 原型要求 |
|---|---|
| P0 | 首版必须完成方向验证级设计：页面骨架、核心对象和一条主交互路径；不追求字段穷举和生产级深度 |
| P1 | 首版设计代表性页面或关键状态，复杂操作使用模拟数据表达 |
| P2 | 首版不做独立完整页面，只保留引用、状态或折叠入口；可在后续版本展开 |
| P3 | 菜单名称和导航入口保留，点击进入统一范围说明页，但业务页面内容不设计；由平台公共能力或后续建设承担 |

> 产品重要性和原型优先级不是同一概念。例如完整审计和密钥生命周期在生产平台中很重要，但其平台级页面不属于本次原型重点；本原型只在 P0、P1 业务场景中细化必要状态和引用。

## 2. 二级菜单：运行管理

| 三级菜单 | 功能组 | 主要功能点 | 产品重要性 | 原型优先级 | 首版原型建议 |
|---|---|---|---|---|---|
| 网关概览 | 环境与实例上下文 | 当前环境、实例名称、实例类型、能力范围、访问入口、运行状态 | 高 | P0 | 与运行情况目录共用实例源；四类实例使用各自示例观测，缺失数据回退未知，不提供环境切换或实例配置 |
| 网关概览 | 服务健康摘要 | 正常服务、异常服务、近 15 分钟请求量、成功率 | 高 | P0 | 使用四个摘要卡快速判断数据服务是否正常，不展示技术配置版本或漂移 |
| 网关概览 | 运行趋势与异常 | 请求量、成功率、最近异常 | 中 | P1 | 使用一张轻量趋势图和最近异常列表，不展开使用统计、日志及告警规则 |
| 运行情况 | 路由清单 | 服务产品、服务版本、环境、调用协议、入口摘要、运行状态 | 高 | P0 | 设计代表性列表、筛选和详情抽屉；首版暂不设计新建流程，不穷举全部路由条件 |
| 运行情况 | 后端与流量 | 后端服务与端口、调用协议、运行状态、QPS、成功率、P95 | 高 | P0 | 主表与只读详情展示运行必需信息，不提供权重调整或注册配置 |
| 运行情况 | 受控运行操作 | 具体调用路由紧急停流 | 高 | P1 | 模拟二次确认、执行结果和审计编号，不提供通用系统运维动作 |
| 策略管理 | 通用网关策略 | 认证投影、限流、配额、超时、重试、熔断、CORS、IP 策略 | 高 | P0 | 设计策略列表、作用范围、绑定关系和简化编辑抽屉 |
| 策略管理 | AI 网关策略 | 固定模型版本、多目标权重、优先级降级、运行健康摘要 | 高 | P0 | 设计最小多目标路由表单与结果摘要，不配置成本、地域、Token 限制或自定义阈值 |
| 策略管理 | 相邻安全能力 | WAF 策略引用、Prompt／内容安全引用、正文采样状态 | 中 | P2 | 只显示外部策略引用和启用状态，不设计 WAF、内容安全或采样规则编辑器 |
| 配置发布 | 发布主流程 | 待发布变更数量、影响对象、基础校验、审批引用、发布状态、结果摘要 | 高 | P0 | 设计待发布摘要、历史列表和简化详情，不展开完整差异或执行引擎 |
| 配置发布 | 历史与恢复 | 发布历史、失败摘要、重试和回滚状态 | 高 | P1 | 保留代表性失败、重试和回滚结果，不展开快照、逐项结果或漂移处理流程 |
| 服务运监 | 分类运行指标 | 应用自身运行、固定服务版本观测、类型化指标与异常 | 高 | P1 | 工作区采用两层应用目录与右侧详情，仅保留收纳式名称查询；服务在右侧查看，模型独立展示 Token 与首 Token 延迟 |
| 服务运监 | 调用日志与追踪 | 请求日志、Payload、Trace、完整调用链 | 中 | P3 | 首版不展示；页面中仅保留 Request ID 等模拟摘要亦非必需 |
| 异常事件 | 服务健康异常 | 服务不可用、成功率下降、响应延迟升高、路由或模型降级异常、配置发布失败 | 中 | P1 | 只设计简要统计和列表，展示事件类型、影响对象、严重程度、状态和时间；不设计详情、规则及通知 |
| 审计日志 | 运行审计 | 管理操作、系统运行日志、外部数据调用、中台数据加工 | 高 | P1 | 设计分类统计、只读明细和类型化详情，关联执行主体、数据应用、服务版本、权限、数据资产、加工批次和结果；不保存敏感正文或提供日志全文检索 |

### 运行管理首版三级导航建议

首版保留全部导航：

1. 网关概览
2. 运行情况
3. 策略管理
4. 配置发布
5. 服务运监
6. 异常事件
7. 审计日志

进入运行管理时默认打开网关概览。其中异常事件、审计日志采用弱化设计：异常事件只保留简化统计与列表，审计日志额外提供轻量详情；两者均不展开规则、通知、全文检索或策略配置。

## 3. 二级菜单：设置

| 三级菜单 | 功能组 | 主要功能点 | 产品重要性 | 原型优先级 | 首版原型建议 |
|---|---|---|---|---|---|
| 租户信息 | 基本信息 | 租户名称、租户编码、状态、当前租户上下文、创建时间 | 高 | P1 | 设计简化的只读详情页；不展开容器隔离或租户资源运维 |
| 租户信息 | 租户级能力摘要 | 已启用环境、服务类型、网关绑定数量 | 中 | P1 | 使用摘要卡片并跳转到环境或网关适配器 |
| 环境管理 | 环境清单 | 开发、测试、生产等逻辑环境，环境状态、网络类型、默认入口 | 高 | P0 | 设计环境列表、详情和环境切换 |
| 环境管理 | 运行绑定 | 环境与统一网关适配器实例绑定、内外网入口、能力状态 | 高 | P0 | 设计绑定关系和状态；不暴露集群、Namespace 或 CRD |
| 环境管理 | 环境维护 | 新建／编辑环境、生产环境标识、启停和风险确认 | 高 | P1 | 模拟表单和风险提示，真实资源创建不在范围内 |
| 服务类型 | 内置类型 | Agent、MCP、模型、Skill、Worker、API、数据流、逻辑表的名称、说明和启用状态 | 高 | P1 | 设计类型卡片或表格；首版以查看为主，可模拟启停 |
| 服务类型 | 扩展定义 | 自定义服务类型、字段 Schema、图标、处理器和厂商扩展参数 | 低 | P2 | 首版不提供自定义类型编辑器 |
| 凭证与密钥策略 | 租户默认策略 | 默认 OAuth 2.0、可选认证方式、API Key 有效期、禁用和轮换规则 | 高 | P1 | 设计简单概览页，展示默认认证方式、允许方式、Key 策略摘要和平台能力入口；不设计密钥生成、查看、轮换和保管 |
| 网关适配器 | 实例管理 | 逻辑名称、适配器类型、厂商类型、管理端点引用、运行端点、环境绑定、连接状态 | 高 | P0 | 设计实例列表、新建／编辑抽屉和脱敏字段 |
| 网关适配器 | 能力声明 | API／AI／Agent／MCP 支持情况，路由、策略、灰度、回滚、监控等能力矩阵 | 高 | P0 | 设计能力矩阵，明确“支持、部分支持、不支持”及对页面操作的影响 |
| 网关适配器 | 接入操作 | 测试连接、刷新能力、启用／停用、查看最近同步结果 | 高 | P1 | 模拟连接测试和刷新结果；凭证仅显示 Secret 引用 |
| 网关适配器 | 基础设施参数 | Kubernetes 集群、Namespace、Pod、CRD、节点、Secret 原文、日志存储和监控采集配置 | 低 | P3 | 首版完全不展示，由云原生基础设施和平台运维系统管理 |

### 设置首版三级导航建议

首版保留全部导航：

1. 租户信息
2. 环境管理
3. 服务类型
4. 凭证与密钥策略
5. 网关适配器

凭证与密钥策略只设计概览及引用关系，不进入平台密钥生命周期。

## 4. 平台能力与业务状态投影的边界

| 平台级能力 | 首版不建设的内容 | P0、P1 场景中需要细化的能力投影 |
|---|---|---|
| 告警 | 告警规则、渠道、通知、升级和处置中心 | 在网关、路由、后端和配置发布中设计异常状态、失败原因及关联入口 |
| 日志 | 调用日志检索、Payload、日志存储和完整 Trace | 在具体对象中设计最近同步结果、执行步骤和失败摘要，不建设通用日志检索 |
| 审计 | 审计策略、全文检索和高级审计分析 | 提供管理操作、系统运行日志、外部数据调用和中台数据加工的结构化审计表格与详情，并在紧急停流等高风险动作中反馈审计编号 |
| 工作流 | 流程设计器、通用任务中心和流程引擎内部页面 | 在配置发布场景中设计审批状态、审批编号、节点摘要、结果及入口，但不建设工作流能力本身 |
| 凭证与密钥 | 密钥生成、明文查看、保管和轮换操作 | 在凭证策略概览、认证策略和网关适配器场景中设计认证方式、脱敏引用、有效状态及平台入口 |

## 5. 场景化设计深度

- P0：每个功能组设计一个主页面、一个代表性详情和一条核心交互路径，用于确认信息架构、对象关系和交互方向，不穷举所有字段、异常和厂商差异。
- P1：设计代表性页面或关键状态，使用模拟数据表达结果，不展开生产级配置和完整生命周期。
- P2：只在 P0、P1 场景中显示必要的引用、状态或折叠内容，不建设独立完整页面。
- P3：保留菜单和导航入口，统一跳转到范围说明页，实际功能页面不设计。
- 平台级能力假设已经存在；当 P0、P1 主路径依赖这些能力时，应在对应场景中细化必要状态、引用、结果和跳转入口。
- 后续页面总体以基础功能、对象状态和结果反馈为设计深度上限；除非验证核心关系所必需，不展开生产级字段、算法、执行步骤或高级配置。

## 6. 运行管理三级页面职责

| 三级页面 | 一句话职责 | 首版核心对象 | 明确排除 |
|---|---|---|---|
| 网关概览 | 汇总当前环境的数据服务健康与实例运行状态，并提供专项页面入口 | 只读当前环境、实例名称与类型、能力范围、运行状态、正常与异常服务、请求量、请求成功率、最近异常 | 配置版本与漂移、路由或策略直接编辑、环境切换、来源产品名称 |
| 运行情况 | 从总览或具体逻辑实例查看运行数据与服务访问状态 | 实例目录、网关请求；注册服务、健康目标、订阅推送；Skill 版本与分发；沙箱执行结果与耗时；各自趋势和明细 | 新建路由流程、权重配置、数据应用创建、产品开发流程、基础设施部署状态 |
| 策略管理 | 集中维护可复用的网关策略及其绑定关系 | 策略、适用产品类型、作用范围、绑定对象、认证投影、限流、配额、超时、重试、熔断、CORS、IP 策略、AI 多目标路由、外部安全策略引用 | WAF 或内容安全规则编辑器、数据应用授权审批 |
| 配置发布 | 以基础状态呈现统一网关配置从待发布变更到审批、执行和结果的过程 | 待发布摘要、发布编号、基础校验、审批引用、发布状态、失败摘要、重试与回滚状态 | 技术配置版本号、完整结构化差异、执行步骤、配置哈希、快照浏览、数据应用版本发版、服务版本发布 |
| 服务运监 | 按应用消费形态及服务类型检查运行状态 | 总览、应用分类与明细、固定服务版本；请求、模型 Token、工具、运行、脚本、任务、订阅各自指标与异常 | 基础设施运维、调用日志、Payload、Trace、告警规则、费用核算、业务结果质量评测 |
| 异常事件 | 以简要统计和只读列表呈现数据服务健康异常 | 持续异常数、近 24 小时恢复数、高严重异常数、受影响服务数、事件类型、影响对象、严重程度、状态、发生或恢复时间 | 详情抽屉、人工处置流程、基础设施事件、手工创建事件、告警规则和通知配置 |
| 审计日志 | 以分类统计、不可修改的明细和类型化详情呈现数据服务运行审计 | 审计类型、执行主体、审计事项、关联对象、执行结果、结果摘要、关联编号；外部调用的数据应用／消费场景／服务版本／认证与权限；中台加工的任务／来源与目标资产／批次／读写数量／耗时 | 请求与响应正文、秘密值、主机或容器日志全文、通用基础设施日志中心、全文检索、导出、审计策略、记录编辑或删除 |

上述页面的信息架构与交互模式需要对照本地配置页面做来源审计：HiMarket 作为主要产品交互参考，Higress 只补充网关配置细节。设计保持轻量，只吸收厂商中立、符合本项目边界的模式，不复制源项目品牌、基础设施参数、代码实现或运行依赖。

本地源码审计结果见[运行管理配置页面本地源码参考](research/runtime-configuration-page-references.md)。其中 HiMarket 提供实际页面交互证据；当前 Higress 本地目录不包含独立控制台前端，只作为配置语义证据。

网关概览保留“摘要卡 → 实例运行状态表 → 请求趋势与最近异常”的结构，页名暂不变。实例表与运行情况左侧目录共用实例分类、实例名称和状态，包含网关、注册中心、AI 治理中心、沙箱；列名统一为实例名称、实例类型、能力范围、访问入口、运行状态、关联对象、最近检查和操作，去除适配器小字。关联对象明确标注服务、Skill 或执行次数，不跨类型合计。三个网关及其余三类逻辑实例均提供离线示例；缺失观测时状态未知、未提供字段显示“—”。顶部请求摘要仍只汇总网关服务。

实例详情从右侧只读抽屉打开，实例名称、类型、状态、能力范围和访问入口与目录及实例表一致；网关显示近 15 分钟上下游 QPS、成功率和 P95，其他类型展示各自的四项核心指标，不套用网关数据。抽屉提供“查看运行情况”，跳转并选中对应实例。仅保留次级“刷新状态”手动刷新展示；统计数据是固定示例，刷新不表示完成后台采集，不提供自动轮询。

运行情况采用左右分栏：左侧为固定高度、独立滚动的实例目录，首项“总览”默认选中，下方按网关、注册中心、AI 治理中心、沙箱展开具体实例；右侧内容独立滚动。总览沿用“四项网关运行摘要 → 上下游 QPS 趋势 → 服务运行清单 → 两组 Top 5”，并增加分类运行摘要入口；网关请求与其他类型计量对象不混合。选择具体实例后，标题、指标、趋势、清单和异常统一切换到该实例；未知观测仍展示“—”和空状态。

注册中心展示注册服务数、健康/注册目标、订阅关系和推送成功率；AI 治理中心按本地 AIRegistry 参考语义展示 Skill 资源数、上线版本、待审核版本和下载成功率；沙箱展示当前执行中、执行成功率、超时次数和 P95 执行耗时。各类型使用两张 3 分钟桶柱图、独立明细表及最近异常，说明收进问号悬停提示；明细和异常入口打开对应记录的右侧只读抽屉。原生字段、适配器派生、统计分母及示例值详见[运行实例指标调研](research/runtime-instance-metrics.md)，不等于已接入生产观测。

页面借鉴本地网关 Dashboard 的信息层级，只选取网关完成流量接入、转发和健康判断所必需的请求量、成功率、响应时间、上下游 QPS 和服务排名。CPU／内存、Pod／容器／节点、工作负载与副本、XDS 控制面通信、网关安装升级扩缩容、日志与监控基础设施属于系统运维，全部不进入当前原型；TCP 字节量和活跃连接属于低层诊断指标，也不作为“运行情况”的必要信息。WAF 命中与拦截属于网关安全能力，但归入策略和异常范围，不在本页展示。

核心列表命名为“网关服务运行清单”，一行代表一个后端服务及端口；关联的服务产品、固定版本和调用路由进入详情，一个产品连接多个后端目标时形成多条运行项。技术注册、同步和部署信息降为详情中的辅助信息。主运行状态统一使用正常、降级、异常、已停流和未知；其他技术状态不得与运行状态并列争夺视觉层级。

运行情况的网关请求总览汇总全部网关服务示例，选择具体网关时仅显示该实例的服务。搜索服务、运行状态与重置放在清单上方，只影响明细及结果数量，不改变实例级指标、趋势和榜单；切换实例清空筛选并回到右侧顶部。详情从右侧只读抽屉打开，服务名称、后端端口、QPS、成功率、P95、固定版本和路由入口与同一示例记录一致。非网关类型使用自己的明细与异常，不显示网关服务清单或请求榜单。

紧急停流仍保留具体调用路由的代表性二次确认演示，不直接停止共享后端；原型不连接真实网关或审计服务。六条网关运行项包含三条正常、一条降级、一条异常、一条已停流。QPS 按同一时段累加，成功率按请求量加权，P95 使用独立汇总观测，不能平均各服务 P95；失败数与同一时段请求量及成功率对齐。两组 Top 5 均采用统一的“序号、名称及次级数值、比例条”行结构，全部条目可打开右侧详情，按当前实例的数据排序；不足五条按实际数量展示，已停流无指标时显示空状态。

策略管理采用单一策略列表，不拆分策略定义与绑定关系标签；自动分配结果只在详情抽屉中摘要展示，不在策略页人工调整绑定。页面保留“新建策略”作为唯一主操作，右侧抽屉先选择策略分类，再按分类显示厂商中立的结构化字段，不使用多步骤向导，也不暴露插件代码、原始 JSON 或适配器实现字段。

首版策略分类包括认证投影、限流与配额、超时／重试／熔断、CORS／IP 访问、AI 多目标路由和外部安全策略引用；WAF 与内容安全规则编辑器不在范围内。策略是当前租户、当前环境中由管理者维护的可复用网关配置，不设置私有／共有范围。一个策略可以绑定多个获准对象；修改定义时必须展示全部受影响对象，只形成配置草稿，经过配置发布后统一生效，不允许静默修改部分绑定。

策略状态分为启用状态与配置状态：启用状态为已启用、已停用；配置状态为已生效、存在草稿、待发布、校验失败。新建、编辑和启停只生成配置草稿，不直接改变当前运行流量；保存后只反馈“草稿已保存”并更新列表状态，不在策略页展开配置发布流程细节。

策略页只定义适用资源类型、资源范围和策略参数，不提供数据应用绑定选择器。数据应用创建或更新并审核成功后，系统根据其已获批准的能力、权限和运行配置自动绑定并分配所需策略；策略详情只读显示已分配的数据应用、服务产品、固定版本和调用路由数量。首版弱化继承顺序与冲突算法，只在保存或自动分配结果中显示“校验通过／存在冲突”，不设计人工优先级配置。

策略列表字段为策略名称、分类、作用范围摘要、自动分配数量、启用状态、配置状态、更新时间和操作。详情抽屉只保留基本信息、当前配置摘要、自动分配摘要和校验结果，不展开完整草稿差异、发布链路或继承关系。

首版完整演示“限流与配额”的新建和保存草稿，以及“AI 多目标路由”的目标模型、权重、降级顺序和运行结果摘要；其他分类只提供真实列表数据和只读详情。编辑复用策略保存前只以数量摘要提示受影响的路由、服务版本和数据应用，范围较大时显示风险提示。只有从未发布且没有自动分配记录的草稿策略可以物理删除；已发布策略只能停用并进入配置发布，历史记录永久保留。

AI 多目标路由参考本地模型监控页的对象和指标维度：目标必须选择已发布的固定模型版本，同一优先级内权重合计为 100%，当前优先级全部不可用后按顺序降级。策略详情只读显示近 15 分钟运行状态、降级次数、QPS、成功率、错误率和 P95；不展示 Token 用量、PV／UV，不复制监控页筛选器、完整图表或来源品牌。

限流与配额表单只保留名称、适用资源、计量指标、限制值、统计周期、突发额度、超限处理和启用状态，数据应用分配不在表单中处理。AI 多目标路由只配置已发布的目标模型固定版本、优先级和权重，不设计成本、地域、语义路由或自定义健康阈值。

策略自动分配属于数据应用新版本发版执行的一部分：数据应用创建或更新审核成功后，系统根据批准结果计算并下发策略；只有策略分配成功，新数据应用版本才整体生效。分配失败或存在冲突时，新版本显示执行失败并保留旧运行版本，不允许部分生效。

策略详情不设计趋势图，只显示近 15 分钟运行状态、QPS、成功率、错误率和 P95；AI 策略增加降级次数，并提供服务运监入口。自动分配只展示已分配的数据应用、服务产品和调用路由数量及最近一次分配结果，不建设完整绑定管理表。

策略列表默认展示八条数据，覆盖六个分类，其中五条已生效、一条存在草稿、一条待发布、一条校验失败，并同时包含已启用和已停用状态。

配置发布采用轻量单页：顶部显示当前环境的待发布变更数量、影响对象数量和基础校验状态，并以“发起发布”作为唯一主操作；下方发布历史表只展示发布编号、变更摘要、状态、发起人、创建时间和查看操作。技术架构明确前不展示 `v1/v2` 形式的配置版本号。

主表使用单一生命周期状态：审批中、待发布、发布中、已生效、失败、已回滚。详情抽屉只展示变更数量摘要、影响对象摘要、校验结果、审批编号、当前状态和失败原因，不展开结构化差异、风险算法、执行步骤、配置哈希或快照。失败重试与回滚只保留确认和结果状态；回滚仍形成新的发布编号。普通路由与策略修改汇总到当前待发布集合，发起后冻结为一条发布记录；紧急停流不混入普通集合，而是自动形成独立紧急发布记录和审计编号。

服务运监替换原“运行监控”页面。工作区采用左右分栏：独立滚动的应用目录在左、运行详情在右。目录固定保留“总览”，按普通客户端、Agent、MCP、Skill、Worker 五种应用主要消费形态分类，分类下列出数据应用，不再展开第三层服务。选中应用后在右侧查看固定版本服务清单，点击服务进入其运行视图，左侧仍选中所属应用，并可通过“返回应用”回到清单。仅保留应用或服务名称查询，放大镜位于“应用目录”标题右端，默认收起；点击后在原标题位置展开输入框，右侧切换为关闭按钮，关闭后恢复标题，不另增一行；标题栏不展示匹配数量。不再提供类型、状态或版本查询。应用分类不等于集市产品类型；模型、API、数据流是服务类型，不因此成为新的应用消费形态。

总览展示匹配应用数、异常/降级应用数、应用服务引用数和缺少应用观测数；下方按应用卡片展示各自消费形态指标，再列出匹配服务。不同应用的请求、执行、工具、脚本或任务不汇总成统一成功率或整体 P95。选中应用后展示应用自身指标、趋势、服务清单与最近异常；选中具体服务后按其类型替换全部指标。应用级自身指标不随名称查询对服务清单的筛选改变，页面明确标注该范围。

普通客户端应用看请求、响应与错误；Agent 应用看结束运行、运行成功率、步骤和工具调用；MCP 应用看工具调用与错误；Skill 应用看激活与脚本执行；Worker 应用看任务完成、队列和重试。服务层另区分七种可调用类型，模型关注输入/输出 Token、首 Token 延迟与降级，业务数据流关注消费量、消费积压和交付延迟。逻辑表不进入可调用服务清单。详细指标与采集边界见[服务运监指标与交互说明](research/service-inspection-metrics.md)。

健康状态使用正常、降级、异常和无数据，缺少外部执行上报时应用状态与执行指标保持未知；仍可查看该应用在平台侧已被观测的 API 调用，不由此推断外部程序健康。名称查询隐藏当前对象后返回查询总览并关闭旧详情；清除或收起查询均恢复完整目录，分类折叠状态跨选择保留。当前仅提供 08-28 13:30–13:45 的固定示例窗口，移除此前只切文案、没有对应观测数据的 1 小时/24 小时快捷按钮。

服务详情采用右侧只读抽屉，应用身份、服务类型、固定版本、指标与最近异常均来自所选的同一条应用服务引用；相同服务名称在不同应用中不共用观测。详情不提供保存、重跑或删除，不展示调用日志、Trace、基础设施信息或健康阈值配置。刷新仅刷新固定示例展示，不表示接入真实监控。

异常事件只采用“简要统计 + 只读列表”。顶部统计持续异常数、近 24 小时已恢复数、高严重异常数和受影响服务数；列表展示异常类型、影响的数据应用或服务产品、严重程度、状态和发生或恢复时间。事件类型只覆盖服务不可用、成功率下降、响应延迟升高、路由或模型降级异常、配置发布失败；严重程度为高、中、低，状态为持续中、已恢复。页面默认近 24 小时，只提供状态、严重程度和关键字筛选，不设计详情抽屉、人工处置、日志全文、通知记录或基础设施事件。

审计日志采用“分类统计 + 只读明细 + 类型化详情”。顶部统计近 24 小时审计记录、外部数据调用、中台数据加工和系统运行日志；列表展示时间、审计类型、执行主体、审计事项、关联对象、执行结果、结果摘要和关联编号，默认近 24 小时，只提供审计类型、执行结果和关键字筛选。审计类型固定为管理操作、系统运行日志、外部数据调用和中台数据加工；执行结果为成功、失败、进行中和已拒绝。

管理操作详情展示影响对象、审批状态和运行影响；系统运行日志详情展示日志来源、事件类型、关联数据应用或服务及处理结果；外部数据调用详情展示数据应用、外部消费场景、服务固定版本、认证方式、服务授权、数据权限、字段范围、结果数量与耗时；中台数据加工详情展示加工任务、来源与目标资产、调度批次、读写行数、耗时、数据权限和失败原因。所有记录不可修改或删除；只保存必要元数据和受控引用，不显示秘密值、请求参数值或响应正文，也不提供主机、容器等基础设施日志全文、全文检索、导出或审计策略配置。
