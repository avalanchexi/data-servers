# 交互与可访问性

## 键盘和焦点

- 所有动作使用原生可聚焦元素。
- 保留清晰的 `:focus-visible`，为浏览器默认键盘行为提供基本反馈。
- DOM 顺序与视觉顺序一致。
- 完整 Tab 顺序、焦点陷阱、焦点归还和纯键盘任务路径只在任务明确要求键盘可访问性时实现。

## 表单

- 每个控件有可见 `<label>`，或有等价的可访问名称。
- 帮助和错误通过 `aria-describedby` 关联，错误字段使用 `aria-invalid="true"`。
- 验证失败说明如何修复；只有任务明确要求键盘可访问性时才要求聚焦第一个错误字段。

## 语义和反馈

- 页面只使用一个 `h1`，标题层级不跳级。
- 表格使用 `caption`、`thead`、`tbody` 和带 `scope` 的表头。
- 状态消息使用 `role="status"`，紧急错误才使用 `role="alert"`。
- 状态不能只靠颜色；图标按钮提供名称，装饰 SVG 使用 `aria-hidden="true"`。

## 视觉要求

- 正文与背景对比度至少 4.5:1，大文本至少 3:1。
- 桌面主要交互目标至少使用 `--ds-control-default`。
- 加载状态保持布局稳定，并避免无法停止的动效。
- `prefers-reduced-motion` 下移除非必要过渡和动画。

## 原型验收

默认走通页面主导航、筛选、主要操作、弹窗确认和关闭，确认视觉状态与反馈完整。只有任务明确要求键盘可访问性时，才追加完整 Tab 顺序、焦点陷阱、焦点归还和纯键盘走查。
