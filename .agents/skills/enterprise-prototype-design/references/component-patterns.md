# 组件模式

## 通用规则

- HTML 与 React 原型均遵循组件规范；本文件与 [设计 tokens](../assets/design-tokens.css) 是来源规范在当前项目中的执行口径。
- 设计前先为页面元素选定适用的组件类型、尺寸和变体，再组合页面；同类组件在不同页面复用一致的结构、样式和状态定义。
- 原型使用语义 HTML 和局部 class，不模拟某个生产组件包的 API。
- 每个交互组件覆盖适用的 default、hover、active、focus、disabled、loading 和 error 状态。
- 控件默认高度使用 `--ds-control-default`；同一表单只使用一种标签布局。
- 组件颜色、尺寸、间距、圆角和层级都来自 `design-tokens.css`。
- 本地规范未覆盖所需组件或变体时，按 [来源说明](provenance.md) 查证官方规范或设计源。无法访问时使用已有组件模式组合，并说明未核对部分；不将推断写成已验证的来源规范。

## React 原型

- 仅在任务明确要求 React 时使用 React；HTML 仍是默认原型格式。
- React 实现沿用上述组件规范，不因技术选型改变组件的结构、尺寸、状态或交互含义。
- 不把来源组件库的品牌名称、Logo、宣传文案或远程资源带入用户界面。
- 不因使用 React 改写本文件已定义的语义、状态、可访问性和业务文案规则。

## 按钮和链接

- 同一任务区只保留一个主按钮。
- 加载中保持原宽并阻止重复提交。
- 链接用于导航，按钮用于动作；不要用可点击的 `div`。
- 图标按钮必须有 `aria-label`。

## 输入、选择和表单

- 占位符只给示例，不能替代可见标签。
- 字段间距使用 `--ds-form-item-gap`；错误紧贴字段，并通过 `aria-describedby` 关联。
- 选项超过 8 项时应提供搜索或更合适的选择模式。
- 提交动作位于表单末尾；错误说明修复方式，任务明确要求键盘可访问性时再聚焦第一个错误字段。

## 表格和分页

- 筛选位于表格上方，批量操作和创建操作分组。
- 表头使用正文尺寸与 medium 字重 tokens，单元格内边距使用 table cell tokens。
- 空值显示“—”；状态使用文字加色彩的标签。
- 分页紧随表格，显示总量和当前位置；筛选变化后回到第一页。

## 弹窗与反馈

- 弹窗用于短任务或阻断式确认，不承载长流程；建议宽度使用 `--ds-modal-width`。
- 弹窗提供明确的关闭与返回路径；任务明确要求键盘可访问性时，再实现移入焦点、焦点陷阱和焦点归还。
- 遮罩点击是否关闭必须与任务风险一致；Esc 关闭只在键盘交互进入任务范围时要求。
- 页面内问题使用字段错误或 Alert；跨区域结果使用状态消息。

## 导航、Tabs 与步骤

- 主导航只表达信息架构。
- Tabs 只切换同一上下文的并列内容，不替代主导航。
- 步骤条只表达有顺序的任务进度。
