# 组件规范

组件外观必须使用 [`tokens.css`](./tokens.css)。React/Tailwind 实现优先沿用参考项目现有 API，并在不改变业务行为的前提下治理视觉差异。

## 基础组件

| 组件 | 允许变体 | 关键规则 |
| --- | --- | --- |
| Button | primary、secondary、danger、ghost；sm、md、lg | 页面主操作至多一个 primary；primary 使用品牌渐变，选择态仍使用纯主色；图标操作必须有可访问名称；loading 时保留宽度 |
| Input / Textarea | sm、md、lg；default、error、disabled、readonly | 标签在控件外；搜索属于只读豁免时仍可操作；错误信息紧邻控件 |
| Select / Combobox / Cascader | 单选、多选、可搜索 | 选项很多时提供搜索；长值省略并可查看完整内容 |
| Tabs | line、card | 一级内容页优先 line；支持方向键、Home、End；禁用项不可聚焦 |
| Card | default、interactive；none、sm、md、lg padding | 主内容卡片不嵌套同等强度阴影；可点击卡片才使用 hover |
| Table / TreeTable | default、compact、sticky、tree | 表头、空态、加载、分页完整；列多时容器内部滚动；操作列保持可见 |
| StatusBadge | neutral、info、success、warning、error | 使用 `--status-badge-padding-*` 保持紧凑；显示业务文本；同一状态在全站保持同一语义色 |
| Modal / Drawer | confirm、form、detail | 短决策用 Modal，长表单或上下文详情用 Drawer；关闭前处理未保存状态 |
| EmptyState / InlineAlert | empty、no-result、no-permission、error | 标题说明发生了什么，描述给出原因或下一步；只有可执行下一步时展示按钮 |
| Pagination | page、page-size | 与列表总数同区域展示；筛选变化后回到第一页 |
| Tooltip | text | 只补充信息，不承载必须阅读的说明或关键操作 |

## 通用状态契约

每个可交互组件至少考虑：default、hover、focus-visible、active、disabled 和 loading。数据组件还需包含 empty、error、partial 和 no-permission。

只读与无权限不是同义词：

- readonly：内容可查看，写操作被禁用或明确拦截；搜索、分页、切换页签等读操作仍可使用；
- no-permission：按安全要求隐藏数据或展示无权限说明；
- disabled：当前状态下操作不可用，应说明条件；
- loading：防止重复提交，保留原操作语义。

组件只能表达权限结果，授权、鉴权和审计仍由平台控制逻辑负责。

## 页面头部

页面头部由图标容器、标题、单行描述和可选右侧操作组成。标题使用页面标题层级，描述使用辅助色。标题过长时优先让描述换行或省略，不能压缩主要操作。

页签紧跟页面头部并共享底部分隔线。内容区自行滚动，标题和页签保持稳定。

## 工具栏

标准顺序为：左侧搜索与筛选，右侧批量操作、次操作、主操作。筛选较多时允许换行或折叠进“更多筛选”，不能把控件压到不可读。

标准表单和独立主操作默认使用 md；高密度工具栏、表格行操作和分页允许使用 sm；强调型页签使用 lg 高度。一个工具栏内的搜索、筛选和按钮保持同一密度，不混用高度。

- 搜索框使用清晰占位词，说明可搜索字段；
- 同组筛选控件保持同一高度；
- 批量操作只有选中记录后才可用；
- 刷新属于次操作，不使用 primary；
- 筛选结果应能被重置。

## 数据表格

表格适合高密度、可比较数据。卡片列表适合对象摘要和跨字段浏览；不要为了视觉丰富把天然表格改成卡片墙。

- 表头用辅助色和中等字重；
- 名称列可用强调正文，ID 和时间保持紧凑；
- 状态统一用 StatusBadge；
- 行内操作优先 1–3 个，更多操作收进菜单；
- 空态占据表格内容区域，不保留伪造空行；
- 列宽可配置，长文本采用省略、换行或详情入口中的一种明确策略。

## 表单与选择器

短表单单栏优先；字段具有明确配对关系时使用双栏。复杂配置按语义分组，不按数据库字段顺序堆叠。

- 必填标记与校验语句一致；
- 帮助文本解释业务含义，placeholder 只展示输入示例；
- 开关只用于即时二元状态，危险开关需要确认；
- 密钥、凭据和敏感值默认遮蔽，并提供受控查看；
- 页脚操作顺序为取消／次操作／主操作，提交期间锁定重复操作。

## 反馈与浮层

短暂成功提示使用 Message；需要用户处理或持续可见的问题使用 InlineAlert；不可逆操作使用 ConfirmDialog。不要同时用弹窗、消息和页面警告重复同一反馈。

抽屉适合保留列表上下文的详情和编辑。全屏编辑器、流程画布和数据开发工作台属于独立页面，不塞进窄抽屉。

## 领域复合组件

- 资产目录：CatalogTree + 资产列表／详情；
- 数据血缘和流程：可缩放画布 + 选中对象属性面板；
- 审批：步骤条 + 当前状态 + 审批记录；
- 数据质量：指标卡 + 趋势图 + 问题列表；
- 数据服务：服务状态、发布审批、授权、运行监控、网关策略与设置；
- AI 对话：用户消息、助手结果、思考／工具过程、建议确认和错误恢复；
- 运行监控：指标卡、趋势图、状态表和异常详情。

复合组件仍由基础组件组成。领域名称和状态取自 `CONTEXT.md`、源码与已确认原型，不由设计系统发明。
