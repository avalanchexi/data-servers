# 页面与原型迁移流程

本流程用于把既有 AgenticOS 页面、HTML 原型或 React 实现迁移到当前设计系统。迁移只替换视觉体系和必要的组件实现，不自动改变业务对象、信息架构、权限、状态、动作、接口或发布流程。

## 自动进入条件

任务满足任一条件时按迁移处理：

- 用户要求迁移、对齐、统一或重构既有页面／原型；
- 目标使用 `--ds-*`、旧 `design-tokens.css`、退役 Skill 或页面自建视觉变量；
- 依据已有页面、源码或截图重建界面，并要求保留原有业务行为。

## Gate 1：冻结业务证据

编辑前读取目标文件、`CONTEXT.md` 和最接近的源码／原型证据，逐项记录：

- 页面名称、导航归属和主要页面模式；
- 字段、状态、动作、步骤、跳转和接口触发；
- loading、empty、error、disabled、readonly、no-permission 和破坏性操作；
- 每项事实的证据位置，以及无法验证的部分。

完成条件：目标范围内每个可见业务对象、状态和操作都有保留结论；无法验证的项已标记为 provisional。

## Gate 2：建立替换映射

按以下顺序映射，不直接复制旧规范数值：

1. 壳层、字体、颜色、间距和局部网格映射到 [`foundations.md`](./foundations.md) 与 [`tokens.css`](./tokens.css)；
2. 控件和状态映射到 [`components.md`](./components.md) 的现有组件或变体；
3. 页面组合映射到 [`patterns.md`](./patterns.md) 的主要模式；
4. 发生证据冲突时读取 [`evidence-index.md`](./evidence-index.md) 与 [`frontend/alignment.md`](../alignment.md)；
5. 规范仍未覆盖时，把决定标为 evidence-derived 或 provisional，并先更新唯一规范源。

`DESIGN-SPEC.md` 只用于识别旧 `--ds-*`、旧类名和历史页面意图，不提供当前视觉数值。

完成条件：每个遗留视觉依赖都有当前 token、组件或页面模式替代；没有无法解释的页面级视觉约定。

## Gate 3：实施迁移

- 先接入 `tokens.css`，再替换壳层和页面级硬编码；
- 复用共享组件 API，保留事件、路由、权限与接口边界；
- 逐一补齐业务证据中冻结的状态，不以“视觉简化”删除内容或操作；
- 只迁移用户授权的页面或目录，不顺带批量改写相邻原型。

完成条件：迁移范围不再依赖退役 tokens、旧 Skill 或页面自建品牌体系，业务证据逐项仍可定位。

## Gate 4：验证与交付

1. 运行 `node frontend/design-system/validate.mjs`；
2. 运行目标已有的相关测试；
3. 页面可运行时，在 1440×900 检查布局、控制台和关键交互；
4. 对照 Gate 1 清单复核内容、状态、操作、权限和溢出策略；
5. 报告已迁移文件、保留的业务行为、采用的规范映射以及 provisional／未验证项。

完成条件：校验与相关测试通过，关键交互可用，且没有未说明的业务变化或遗留视觉依赖。
