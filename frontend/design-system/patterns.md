# 页面模式

所有模式共享同一桌面壳层和页面头部。先选择最接近用户任务的模式，再组合组件；不要从空白画布随意拼装。

## 1. 列表管理

适用：用户、角色、API、任务、数据资产、审计记录。

```text
页面头部
页签（可选）
搜索与筛选 | 批量操作 / 新建
数据表格
分页与总数
```

必须包含 loading、empty、no-result、error、no-permission 和有数据状态。行点击与行内操作不能互相冲突。

## 2. 对象详情

适用：资产 360、API 详情、任务详情、策略详情。

```text
返回 / 对象标题 / 状态 / 主操作
摘要信息或核心指标
详情页签
属性、关系、版本、记录等分区
```

只读详情使用键值或描述列表；可编辑字段通过明确的“编辑”进入表单态，不把文本展示伪装成禁用输入框。

## 3. 新建与编辑

适用：API 开发、服务注册、规则和系统配置。

- 简单对象：单页分组表单；
- 有清晰阶段的复杂对象：步骤式表单；
- 需要上下文预览：编辑区 + 预览／说明双栏；
- 需要大画布：独立工作台，顶部放保存、校验、提交审批和版本信息。

始终区分保存草稿、校验、提交审批和发布。设计系统不把这些业务动作合并成一个模糊按钮。

## 4. 系统配置

适用：环境配置、应用配置、字典、策略。

配置项按管理对象分组，展示作用域、当前值、来源、最后更新时间和操作。高风险配置需要变更确认与审计提示。底层配置与应用内配置使用相同组件，但通过作用域和归属文案区分。

## 5. 监控与审计

适用：运行监控、调用统计、系统审计、质量监控。

```text
时间范围 / 范围筛选 / 刷新
核心指标卡
趋势与分布图
异常或事件表
详情下钻
```

指标必须带单位和时间范围。颜色表达阈值而非装饰；图表下钻后能回到原筛选上下文。AgenticOS 运行监控与数据服务调用监控可保持独立入口，但使用同一视觉语言。

## 6. 树表与数据资产

适用：资产目录、组织、功能菜单、分类分级。

左侧树负责范围定位，右侧承载列表或详情。树宽保持稳定，节点支持搜索、展开和选中；右侧状态随选中对象变化。空选中、无子节点和无权限需要分别表达。

## 7. 数据服务

数据服务页面沿用已确认的六个任务入口：服务集市、数据应用、授权审核、运行监控、网关策略、设置。运行监控包含网关概览、运行情况、服务运监、异常事件和审计日志；网关策略包含策略管理和配置发布；设置采用目录与详情模式，包含集市产品类型、认证与密钥策略、类型专属限制。页面结构取自 `asset-service-prototype.html`，视觉使用本设计系统。

开发完成并通过审批的 API／AI 能力才进入 AI/API 网关；界面需明确开发态、审批态、上线态和下线态。网关注册能力的鉴权、授权、流控和审计属于能力治理信息，应在详情和状态中可追溯。

## 8. AI 与 API 开发工作台

适用：API 编辑器、编排、AI 服务开发。

推荐三区域：资源／节点导航、主编辑画布、属性／调试面板。顶部操作区展示保存状态、版本、校验、试运行、提交审批。日志和调试结果作为可折叠下方面板，不与属性编辑争夺主空间。

## 9. AI 对话与结果

用户输入和助手结果在同一主内容流中；工具调用、思考步骤和跨 Agent 建议使用次级面板。建议确认必须提供明确候选项和取消路径。长报告、图表或数据表采用内容卡片，不塞入狭窄消息气泡。

## 10. 空态、错误与无权限

状态页保持当前页面头部和导航上下文，只替换内容区域：

- 首次空态：说明尚未创建什么，并提供主操作；
- 筛选无结果：保留筛选，提供重置；
- 加载失败：说明失败并提供重试；
- 无权限：说明受限范围和申请路径；
- 功能未开放：说明可用条件，不伪装成加载中。
