# AI 使用与验收指南

本指南约束 AI 如何使用设计系统，不复制 [`tokens.css`](./tokens.css) 中的数值。

## 开始前

1. 读取根目录 `CONTEXT.md`，确认产品术语和对象关系；
2. 识别任务是新设计、原型迁移、React 实现还是视觉审查；
3. 读取 [`foundations.md`](./foundations.md)，再按任务读取 [`components.md`](./components.md) 和 [`patterns.md`](./patterns.md)；
4. 查找最接近的真实系统、源码或原型证据，列出必须保留的内容、状态和操作；
5. 不能验证的领域视觉决定标为 provisional，不伪装成目标系统事实。

## 新设计

- 先选择页面模式，再填充业务内容；
- 使用统一壳层、页面头部和 token，不从截图逐像素复制偶然差异；
- 只创建完成任务所需的组件变体；
- 同时设计理想状态和 loading、empty、error、no-permission、disabled 状态；
- 写操作必须体现权限结果、确认、反馈和审计入口，但不在前端视觉规范中发明授权逻辑。

## 迁移现有原型

迁移既有页面、旧 `--ds-*` 原型或 React 实现时，执行 [`migration.md`](./migration.md) 的四个 Gate。该文件是迁移顺序与完成条件的唯一来源；本指南不维护第二份流程。

## React/Tailwind 实现

- 保持 React 19、TypeScript 和 Tailwind CSS 4 的现有技术习惯；
- 全局导入 `tokens.css`，颜色、阴影、圆角和关键尺寸使用 CSS 变量；
- 优先复用或治理 `src/components/ui/` 中已有 API，不为单页创建近似组件；
- Tailwind 负责 flex、grid、overflow 和响应组合；设计数值由 tokens 提供；
- 保留 `data-ro` 等只读交互语义，写权限判断继续由现有权限层负责；
- 页面级硬编码只允许数据可视化计算值或无法 token 化的内容尺寸，并需可解释。

## HTML 原型

- 直接链接 `tokens.css`；
- 使用语义 class 名，不把颜色或尺寸写入大量内联 style；
- 原型交互至少覆盖页签、筛选、弹窗／抽屉或关键流程中的实际状态变化；
- 假数据需明显可替换，不伪造真实用户、密钥、审计或生产统计；
- 基准视口检查 1440×900，同时确认不低于桌面最小宽度时没有意外遮挡。

## 视觉审查

按严重度报告：

- P0：内容不可用、重要操作被遮挡、权限或破坏性动作表达错误；
- P1：壳层、组件、状态或业务流程偏离规范；
- P2：间距、字号、颜色、圆角和对齐不一致；
- P3：不影响任务的轻微视觉优化。

审查时给出文件与位置、违反的规范、可观察影响和修正方式。不要只写“看起来不一致”。

## 完成清单

### 内容与结构

- [ ] 产品术语与 `CONTEXT.md` 一致；
- [ ] 页面归属、字段、状态和操作有源码或原型依据；
- [ ] 已选择并遵循一个主要页面模式；
- [ ] 空、加载、错误、禁用和无权限状态完整。

### 视觉

- [ ] 使用 `tokens.css`，没有引入 `--ds-*` 或页面自建品牌色；
- [ ] 页面标题、区块标题、正文和辅助文字层级清晰；
- [ ] 壳层、主卡片、间距和局部网格符合 `foundations.md`；
- [ ] 主操作唯一，状态色具有业务语义；
- [ ] 1440×900 下无非预期滚动、裁切和重叠。

### 交互与实现

- [ ] 控件包含键盘焦点、disabled 和 loading 状态；
- [ ] 搜索、筛选、分页和页签在只读模式下仍可使用；
- [ ] 危险操作有确认与反馈；
- [ ] 表格和长内容有明确的溢出策略；
- [ ] 已运行 `node frontend/design-system/validate.mjs`。
